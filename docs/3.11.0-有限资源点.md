## 一、这是什么

在野外放三类**有真实库存、会真的被采空**的资源点，玩家靠眼睛发现、靠工具和判断处理：

| 模板 | 世界里是什么 | 数量 | 能否恢复 |
|---|---|---|---|
| 蛊材生长地 | 真实的丹心草 / 雷鸣草（本体方块） | 4–8 株 | 根在、环境合法、已加载时才长，每 3 游戏日最多 +1，终身最多 +4 |
| 玄金露头 | 真实的玄金矿方块 | 3–6 块 | **永不恢复** |
| 元石露头 | 真实的元石矿方块（`fangkuaiyuanshiyuankuang`，掉元石） | 3–6 块 | **永不恢复** |
| 赤炼金露头 | 真实的赤炼金矿方块（`chilianjinyuankuang`，掉自身） | 3–6 块 | **永不恢复** |
| 温鼎石露头 | 真实的温鼎石矿方块（`wen_ding_shi_kuang`，掉温鼎石） | 3–6 块 | **永不恢复** |
| 守护资源地 | 单个木桶 + 一只按地形选出的真实蛊兽 | 4–8 份蛊材 | 取空即止，不补货、不补生 |

不依赖 NPC 对话、关系、任务、势力或追捕。天意仍然在幕后：玩家看到的是资源、兽和现场痕迹。

## 一之二、地形门控（「找材料先找地形」）

本体有 15 个**流派专属地形**（`data/guzhenren/worldgen/biome/`）。资源点不再随便落在任何地方，
而是**先看候选点的真实群系，再决定这里能出什么模板**：

| 地形（真实群系 id） | 允许的模板 |
|---|---|
| `guzhenren:suijinqiulin` 碎金丘陵（金道） | 玄金露头、赤炼金露头、守护资源地 |
| `guzhenren:lianxuangudi` 炼玄谷地（炼道） | 温鼎石露头、守护资源地 |
| `guzhenren:wanrenqianshan` 万仞千山（土道） | 元石露头、守护资源地 |
| `guzhenren:cangmulinhai` 苍木林海（木道）、`guzhenren:misihuanlin` 迷思幻林（智道） | 蛊材生长地、守护资源地 |
| 其余 11 个流派地形 | 只有守护资源地 |
| 原版群系 | 蛊材生长地（10 个温和群系）+ 守护资源地 |

守护资源地**故意不设地形门槛**：木桶和兽可以出现在任何自然地表（与 3.11.0 一致），
只有「兽的种类」随地形变化。理由是——万一整合包世界里这 15 个数据包群系根本没生成，
把守护地也锁进地形就会让它在整局游戏里永不出现，「启用后必须真的能生成」直接落空。

判定是**逐槽位**的：一个点的所有方块都必须落在允许的群系里，否则这个模板在这里不生成。
**地形不匹配只是「这次不生成」，不是全局禁用**——换个位置、换个地形，模板照常参与。

### 守护兽按地形匹配

守护资源地的守护兽不再是固定灰狼/土狼，而是按所在地形挑：

| 地形 | 守护兽 |
|---|---|
| 雷泽 `leize` | 豪电狼 `guzhenren:hao_dian_lang` |
| 碎金丘陵 `suijinqiulin` | 虎 `guzhenren:hu` |
| 赤焰烬土 `chiyanjintu` | 火焰熊 `guzhenren:huoyanxiong` |
| 万仞千山 `wanrenqianshan` | 垚犽犬 `guzhenren:yao_ya_quan` |
| 其它地形 | 退回灰狼 `hui_lang` / 土狼 `tu_lang`（优先灰狼，顺序固定、不随机） |

本体的「转数威压」等 AI 行为**完全不动**：不加 `setTarget`、不拴绳、不传送、不设竞技场边界。
玩家转数够高时兽本来就会退开，这正好是「可绕行、可偷采」的天然支撑。
**绝不添加击杀奖励**（本体死亡过程自己的掉落就是全部），**绝不补生**。

## 二、玩家怎么玩

1. 在出生点 128 格外的自然地表，可能出现资源点（距离玩家 48–128 格）。
   出现什么**取决于脚下是什么地形**：走到碎金丘陵才容易撞见玄金/赤炼金，炼玄谷地才有温鼎石，
   万仞千山才有元石，林子里才多蛊材。找材料先找地形。
2. 走到跟前，《见闻录》会记一条**本人亲见**（记录的是你自己站的位置，不是资源点坐标）。
3. 蛊材丛可以直接采；矿要带镐；守护地可以正面打、用陷阱、把兽引开、或者趁它走远偷采。
4. 采空后：矿和守护地就此结束；蛊材丛只要根还在，会慢慢再长，但总额有上限。
5. 把根基或木桶毁掉，这里就永久绝了——不会因为重启、重进区块又长回来。

## 三、怎么启用

默认**全部关闭**，装上去不会改变现有世界。编辑 `config/tianyi-sites-server.toml`：

```toml
enabled = true            # 总开关
plantEnabled = true       # 蛊材生长地
oreEnabled = true         # 矿石露头（下面是逐个模板的开关）
guardedEnabled = true     # 守护资源地
```

三种新增露头还有**各自的开关**，默认同样关闭；只开 `oreEnabled` 不会自动放出新矿：

```toml
yuanshiOutcropEnabled  = true   # 元石露头（万仞千山）
chilianOutcropEnabled  = true   # 赤炼金露头（碎金丘陵）
wendingOutcropEnabled  = true   # 温鼎石露头（炼玄谷地）
```

先只开玄金、确认无副作用，再逐个开新矿，是推荐的上线顺序。
老模板（蛊材/玄金/守护地）没有独立开关，仍只受对应的 kind 开关控制，行为与 3.11.0 相同。

有领地/保护插件的整合服建议再开严格模式：

```toml
strictRegionMode = true
adminMinChunkX = 0
adminMaxChunkX = 0
adminMinChunkZ = 0
adminMaxChunkZ = 0
```

严格模式下，只有这个主世界区块矩形内、且没有保护插件拒绝的位置才会生成。
**DENY 永远不被绕过**；没有保护插件时普通原版环境按正常规则放行。

启用后若运行时复核发现方块/物品/实体注册或掉落表与预期不符，**只跳过本轮并告警一次**，
不会永久禁用整个玩法，也不会随机换一个替代资源。

## 四、不变量（实现里真正守住的）

- **容器/方块是唯一库存来源**：账本只记批次与对账，不按账本发货。实物比账本多视为冲突，不补账。
- **不重复发货**：木桶放入前必须是空的；放入后立即校验数量与物品；放置被事件取消时**不发放任何库存**。
- **不补货**：采空、载体毁坏、区块卸载都不会触发补发；离线时间不补算生长。
- **不补生守护兽**：实体缺失或卸载一律视为未知，既不算死也不再生成一只；只有匹配 UUID 的死亡事件才确认。
- **无额外击杀奖励**：守护兽掉落完全由本体自己的死亡过程决定，天意不加任何奖励。
- **事务化物化**：准备→已应用→已提交。崩溃后未决事务**逐站隔离**，不重放、不补货；其余站点继续可用。
- **上限**：每 200 刻最多检查 4 个候选、落地 1 点；8×8 区块至多 1 点；全局 64；不强制加载任何区块。
- **地形不匹配不替代**：群系不在白名单就跳过该候选，绝不换地形、换材料、换兽来凑一个点。
- **未知类名不瞎猜**：只有灰狼/土狼与玄金的 java 类名经过字节码审阅；豪电狼/虎/火焰熊/垚犽犬
  与三种新矿方块**只按注册表 key + 真实掉落表**核验。核验不过 → 本轮不生成 + 告警一次，不永久禁用。

## 六、已知边界

1. 「玩家用泥土/石头自己搭的建筑」也可能被判为自然地形——方块层面无法彻底区分，按已知弱保证保留。
2. 32 格避让扫描是保守策略，单次耗时需实机测量。
3. 若站点长期卡在物化中（玩家占了格子），需管理员退役该点，否则占用一个全局名额。
4. 未决事务与损坏记录的恢复入口是管理员级的单站操作，没有自动修复。
5. 生长只在已加载时累计，所以「挂机不刷、下线不长」。
6. **元石「地下」这一支没实现**：生成器只在 `WORLD_SURFACE` 高度图取点，没有地下取点策略
   （也不为地下强加载区块），所以元石只出现在万仞千山地表。宁可少一条来源，不假装支持。
7. **蛊材生长地仍要求原版泥土类土壤**：guzhenren 群系的表层方块尚未核实；
   若其表层是自定义方块，植物在苍木林海/迷思幻林里会因土壤判定失败而不生成（保守：不生成、不替代）。
8. **四只地形守护兽的 java 类名未 dump**：目前只按 `BuiltInRegistries.ENTITY_TYPE` 的 key 校验身份，
   它们的生成/死亡 procedure 也没审阅。若某只兽的 `finalizeSpawn` 在实机上失败，该站点会被**隔离**
   （不补货、不重试），需管理员退役。建议上线顺序：先在已知安全区只开 `guardedEnabled` 观察一轮，
   确认灰狼/土狼正常后，再进入 15 个流派地形。
9. **地形门控只作用于新生成的点**：3.11.0 之前已经落地的点（例如原版群系里的玄金露头）不会因为
   新增白名单而被退役，仍按原规则对账、物化、采空。要收紧只能等它们采空后自然退役。
