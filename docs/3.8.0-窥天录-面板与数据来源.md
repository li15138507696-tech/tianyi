# 3.8.0：《窥天录》玩家见闻面板

> 面板是游戏化外壳；原著感来自「机缘可能是诱饵、旁人的逐利可能构成人劫、布局要一层层识破」。
> **本面板没有一项在真实游戏里跑过**——见文末「验证边界」。

## 一、它解决的核心问题

工程里原本有三份不同的「知道」：

| 谁 | 存在哪 | 含义 |
|---|---|---|
| 天意 | `Knowledge.Store` / `Wiki` | 世界意志掌握的情报 |
| NPC | `IntelState` + `IntelNet` | 居民之间传播的见闻 |
| **玩家** | **本面板新建** | 这个玩家有依据知道的事 |

面板**不读前两份**。它只有自己的一份玩家档案，由服务端按玩家筛选后下发。
所以「客户端隐藏」这条路根本没走——拿不到就是拿不到。

## 二、数据流

```
真实事件（拾取/产地出货/雷/上门/灾劫/杀兽）
   ↓ 只有当事人亲历，才写进他自己的档案
PlayerJournal（纯逻辑，可离线测试）
   ↓ JournalStore：存在玩家 persistent data 的 tianyi/journal 下
JournalSyncPayload（服务端按玩家构造，最多 60 条）
   ↓ PacketDistributor.sendToPlayer（带 10 刻限流）
JournalClientState（客户端只持有这一份）
   ↓
JournalScreen（只负责画）
```

动作方向相反，且**服务端重校验**：

```
点击 收藏/存疑/记入疑局
   ↓ 只发「动作 + 条目 id」，不发内容
JournalNet.handleAction → 按玩家重新读档 → 条目必须属于他 → 才改 → 回一次同步
```

## 三、四页与它们的**真实**数据来源

| 页签 | 内容 | 已接入的来源 | 未接入 |
|---|---|---|---|
| **观象** | 最近发生的异常 | ① 亲手拾得蛊材（拾取 Post 事件的真实差值）② 自己名下产地出货 ③ 诱饵被捡走时的雷雨 ④ 人劫 NPC 真的出现 ⑤ 自己渡过的灾劫 | NPC 对话传闻（本体没有可用的对话产出接口）、产地"减产"的独立记录（现在只在出货时记一条） |
| **察局** | 把见闻关联成疑局 | 玩家点「记入疑局」→ 归入「未名疑局」，结论按证据数/来源数/存疑标记算成四档 | 自动关联（当前不做：没有可靠规则就不硬凑） |
| **藏识** | 经得起验证的认识 | ① 亲手打过的兽类 ② 炼制**尝试**（结果一律「未核实」） | 产地采收历史、已核实传闻来源 |
| **行藏** | 自己留下的痕迹 | 有载体看着的当众击杀 | 公开交易、身份切换、来源不明的持有物、过时行踪 |

**没有可靠来源的事件不生成**。四页在没数据时显示「尚无相关见闻」，不写"此地安全"。

## 四、题名解锁

- 默认题名 **见闻录**；
- 解锁条件（全部来自实际内容）：亲见 ≥ **3** 条，**且**至少一条已记入疑局；
- 解锁后才显示副题「所见未必为真，所得未必为福」（界面原创文案，不是原著原文）；
- 不看游玩时长、不发传承、不造新蛊虫。

## 五、界面与交互

- 按键 **J**（`key.tianyi.journal`，可在「按键设置 → 天意」里改绑）；
- Esc 或再按 J 关闭；**不暂停**世界（多人可用）；
- 横向旧卷册：左目录 / 中列表 / 右正文；
- 列表与正文都可滚动；小窗口按可用宽高等比缩放；
- 三个按钮：收藏 / 存疑 / 记入疑局；
- 「存疑」只是个人标注：**不触发雷电、不算识破、不给奖励**。

## 六、炼蛊口径的修正（本轮）

以前（3.7.0/3.7.1）会把「背包差分里唯一新增的那项」当成炼成产物，并据此写
`Knowledge.Kind.CRAFT` 与身份案的手艺痕迹。

**本轮按审查要求改掉**：差分会被同期拾取/交易/取出污染，不能单独证明炼制成功。
现在：

- 只记一条**藏识**条目：「炼制尝试：结果未核实」，附上疑似产物与数量；
- **不再**写 `CRAFT` 事实，**不再**写 `CRAFT_TRACE` 身份证据；
- 这由审计静态锁住（`noteAlchemyAttempt(` 必须在、`Knowledge.Kind.CRAFT` 与
  `CRAFT_TRACE` 不得出现在炼蛊见证里）。

## 九、3.8.1：一次真实的实机崩溃与修复

3.8.0 装进整合包后**崩在加载期**，这是本功能第一次真正上机，教训值得记下来。

### 现象

`
ResourceLocationException: Non [a-z0-9/._-] character in path of location: minecraft:tianyi:journal
  at JournalSyncPayload.<clinit>  →  JournalNet.registerPayloads
  → Mod loading issue for: tianyi
`

### 根因（字节码已核）

CustomPacketPayload.createType(String) 的内部实现是：

`
createType(String)  →  ResourceLocation.withDefaultNamespace(String)
                    →  new ResourceLocation(minecraft, assertValidPath(minecraft, arg))
`

也就是说它把传入的字符串当成 **path**，命名空间写死 minecraft。
所以 createType(tianyi:journal) 得到的是非法 id minecraft:tianyi:journal，
在 <clinit> 里直接抛异常 —— 整个 mod 的包注册失败。

### 修法

`java
// 错：整串被当成 path
CustomPacketPayload.createType(tianyi:journal);

// 对：显式给命名空间
new CustomPacketPayload.Type<>(
        ResourceLocation.fromNamespaceAndPath(tianyi, journal));
`

### 防回归

审计新增静态锁：
et/ 下**禁止出现 createType(**；所有 romNamespaceAndPath
的命名空间必须是 	ianyi、path 必须匹配 [a-z0-9/._-]+。断言前会先剥掉注释，
避免注释里提到旧写法被误判。

### 附带修掉的两处

- 启动日志里把版本号写死成 3.0.0（实际是 3.8.x）→ 改成从 ModList 读真实版本；
- 新增一行启动日志提示按键入口，方便玩家知道有这本册子。

### 关于同一份崩溃报告里的 iris

那份报告的主描述是 Mod 'iris' failed while registering config options
（NullPointerException: Mod with id iris not found in ModList），涉及
sodium 0.8.13-beta 与 iris 1.8.14-beta 的版本配合。

时间线上我们的 payload 异常（11:09:52）**早于** iris 的 NPE，因此不能排除
「先有一次 mod 加载失败、后面判定环境不完整」的连带影响；但 iris 那一处
属于那两个性能 mod 的版本搭配问题，与本面板无关。装 3.8.1 后若 iris 仍崩，
那是整合包自身的 sodium/iris 版本问题，不是本模组。
