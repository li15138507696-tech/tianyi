# 3.14.0 天意强度（WillForce）

> 本文件写清「天意强度档位」到底改了什么、每个档位实际会发生什么、玩家能看到什么。
> 所有数值都是**原创平衡参数**（`[平衡参数]`），不是原著数值 —— 原著只给
> 「天意维持天地平衡、制约威胁、利用棋子」这类**定性**描述，没有任何数值。
> 本版本**未实机验证**（边界见文末）。

---

## 1. 为什么要这个档位

3.13 之前，天意的压制、灾劫、兽群三条渠道由旧开关 `legacyAutomaticPressure`
单独控制，而它**默认关闭**。结果就是：世界后备系统全在，但玩家几乎感觉不到
「世界在针对自己」。

3.14 把「出不出手、出多重的手」收拢成一个 0..3 的档位，并让这个档位真的被
决策器与执行层读到 —— 而不是新增一个写着数字却没人的枚举。

**纪律：档位只做乘数与阈值。** 没有第二套压制/灾劫/兽群系统：

| 原有类 | 档位改它什么 |
|---|---|
| `will/WillCore` | 动作条数上限、窗口配额、意志消耗倍率、是否选灾劫渠道 |
| `will/Assessment` | 失衡阈值、死区、压制门槛、扶持门槛 |
| `will/Calamity` | 灾劫规模倍率（不新增种类，针对性上限不动） |
| `will/Opportunity` | 诱饵判定的门限（占比仍受硬上限约束） |
| `will/Ploy` | 同时存在的布局上限（人劫频次的上限侧） |
| `will/BeastHerd` / `world/BeastHerds` | 借兽与兽潮的规模（仍从真实种群扣） |
| `world/WorldExec` | 灾劫规模/冷却、借兽规模、人劫酝酿、诱饵门限 |
| `world/WillServer` | 决策周期、单轮执行条数、压制渠道开关、现象巡查周期 |

## 2. 配置

新文件：`config/tianyi-force-server.toml`（服务端配置，`Type.SERVER`）。

```toml
intensity = 1   # 0 关闭 / 1 温和（默认）/ 2 严厉 / 3 天倾；越界会被夹到 0..3
```

**与旧开关的关系（旧配置不改名、不删除）**

```
压制渠道是否放开 = EncounterSettings.legacyPressure() 或 intensity >= 2
```

- 老整合包把 `intensity` 留在 0/1、显式打开 `legacyAutomaticPressure` → 行为与 3.13 一致。
- 新玩家把 `intensity` 调到 2/3 → 即使旧开关仍为 false，压制与灾劫也会真的发生。
- `legacyAutomaticResources` 与本次档位**无关**：实物产地（`ResourceSite`）仍只由它控制。

## 4. 每个档位实际会发生什么

### 0 关闭 — 零干预

- `WillServer.runDecision` 在**任何观测与评估之前**直接返回；`WillCore.decide`
  在产生任何意图之前返回空表（顺序由 `audit_will` 核对）。
- 不推进情报、不推布局、不推灾劫、不做现象巡查、**也不兑现成熟机缘**
  （兑现会在世界里开出产地，那同样是天意出手）。
- 灾劫/兽潮/枯损/诱饵的开关全为 0，诱饵门限 2.0（`|sin| ≤ 1`，永远不成立）。
- 唯一的残留是既有的定期维护（仙窍内部时间、兽群种群自然增长、寿蛊供给、
  有限资源点产出），它们与天意档位无关，不属于「天意出手」。
- 想要「保留实物资源渠道、但不要天意施压」，应把档位设成 **1** 并另外打开
  `legacyAutomaticResources = true`，而不是用 0。

### 1 温和（默认）— 只有世界现象

- **不**主动压制、**不**降灾劫、**不**放兽潮。
- 会做：天象转阴（可能带闷雷）、近处产地枯损、小规模兽群迁徙。
- 概率都很低（每 4 游戏小时一次抽样；枯损每天最多一次；迁徙看真实种群有没有货）。
- 缘于旧逻辑的其余部分照旧：扶持/机缘仍在跑（但实物兑现仍要求
  `legacyAutomaticResources = true`），见闻录、有限资源点、妖兽名录、宿命账本不变。

### 2 严厉 — 既有压制渠道真的打开

- 压制渠道（`SUPPRESS` 的 BEAST / RUMOR / RESOURCE / FACTION、`HOLD_HEAVEN`、
  人劫 `Ploy`、灾劫推进）**在旧开关关闭时也能落地**。
- 压制门槛从 0.55 降到 0.42：0.42–0.55 之间的「威胁」从「看着」变成「动手」。
- 灾劫从「几乎不发生」变成真实发生：`WillCore` 会对头号威胁/失衡头目按窗口概率
  选 `CALAMITY` 渠道；`WorldExec` 开灾劫时乘规模倍率、加同目标冷却与总量上限。
- 天象更频繁并带雷；偏离落雷出现（落在 5–12 格外，不劈在玩家身上）。
- 产地枯损更常见（0.35 比例 / 64 格内），玩家会看到「那片蛊材忽然枯了」。

### 3 天倾 — 更密、更重，并允许兽潮

- 压制门槛 0.32、单轮 4 次压制、窗口配额 4 次/3 日、意志消耗 0.70。
- 灾劫概率 0.60、规模 ×1.35、同目标冷却 6000 刻、同时最多 4 场。
- **兽潮**：每 12 游戏小时有 0.45 概率，一次想赶 12 只；**只能**从
  `BeastHerds.driveToward` 走真实兽群账 —— 生成一只少一只，种群不足就是 0，
  绝不凭空生成（旧代码里「无种群兜底生成一只」在 3.7.1 就删掉了，这里也不会回来）。
- 天象 0.55、落雷 0.45、枯损 0.50（0.55 比例 / 96 格）。

## 5. 玩家能看到什么（隐性约束不破）

天意仍然**没有**面板、没有好感度、没有威胁评分、没有「奖励到账」、没有聊天播报。
`world/` 层依旧不 `sendSystemMessage` / `displayClientMessage`（`audit_will` 每次构建都查）。

玩家能感知的三条渠道（全部是真实世界变化）：

1. **天象**：天色转阴、闷雷、偏离的落雷；
   「被盯上」时（天意内部的姿态已经是压制）天象概率加倍 —— 玩家只会觉得
   「怎么偏偏这几天天不好」，看不到任何判定；
2. **物候**：最近那处产地储量被打散、恢复变慢，直到变成「荒」/「毁」；
3. **兽讯**：兽群朝这边挪动（杀得越多、种群越薄，就越是赶不出兽）。

这些观察会进**玩家自己**的《见闻录》（观象页），走既有的 `JournalStore` 与
既有同步包（**没有新 payload、没有新注册 ID**）：

- 「天忽然阴了下来」「远处闷雷不断」「风向莫名其妙地反了」「云压得很低」
- 「那片蛊材忽然枯了」
- 「兽群忽然朝这边聚过来了」

条目去重键是 `force|<种类>|<窗口号>`，同一现象同一 4 游戏小时窗口只记一条；
正文只写看见的那一面，不写后台判定（例如不会出现「威胁值 0.62」）。

## 6. 幂等与守恒（为什么不会重复结算 / 不会凭空生东西）

- **窗口幂等**：每次现象是否发生由 `WillForce.fires(kind, subject, now, window)`
  决定；起点是 `(窗口号, 主体, 种类)` 的确定性 FNV-1a 哈希，区间长度等于巡查周期，
  所以「一个窗口恰好命中一次」，且不依赖任何运行时状态表 —— **重启不会补发一次**。
- **事件键**：`WillForce.eventKey(...)` 给出 `force|<kind>|<subject>|<窗口号>`，
  见闻录与其它可能的记录都用它去重。
- **不凭空生成**：兽潮只走 `BeastHerd.drive`（`Math.min(能赶的, 想要的)`，扣真实种群）；
  产地枯损只走 `ResourceSite.scramble`（**减**储量，不产出物品）；
  灾劫只开既有四等四阶段，不新增种类，不改针对性上限（0.45），不额外送道痕。
- **不写玩家背包**：现象层没有任何 `addItem` / `setItem` / 背包写入（审计逐次核对）。
- **不强制加载、不全图扫描**：只看已加载位置与被载体覆盖的在线玩家，
  `level.isLoaded(pos)` 为假就跳过；不 `setChunkForced`、不 `getChunk`。

## 7. 未实机边界（必须与「已验证」分开）

本轮**没有进游戏**。以下都只有静态/离线证据，不能算已验证：

- 天象（`setWeatherParameters`）与落雷在真实存档里的视觉/音效表现；
  落雷是否会误伤附近的玩家或点燃方块（落点固定离目标 5–12 格，但地形不可控）。
- 兽潮在真实兽群分布下的体感：本版本只保证「不凭空生成」，
  不保证「一定会出现在你面前」（种群不足、区块未加载就什么都不会发生）。
- 灾害（地灾/天劫/浩劫/万劫）在 1.21.1 实机下的粒子/音效/伤害表现。
- 产地枯损在多人与区块反复加载下的观感（只改储量与恢复率，不改方块）。
- 《见闻录》新条目的排版与检索（复用既有界面，未新增页签）。
- 配置热重载：`Type.SERVER` 配置在整合包里通常需重启生效，未验证运行期改动。
- `intensity` 连续改档（例如 3 → 0）时，已经开着的灾劫/布局不会被立刻收回：
  它们由各自的既有生命周期走完（灾劫走完四阶段、布局到期失败）。
  这是刻意选择：档位不改写已经发生的事。

已知未实现（明确不算完成）：

- 「器物裂纹」：会让玩家手上的东西掉耐久，属于**改玩家物品**，与本轮
  「world/ 不写玩家背包」的纪律冲突，故不做。
- 机缘的**实物兑现**仍要求 `legacyAutomaticResources = true`；
  档位只改诱饵比例，不解锁资源渠道。
