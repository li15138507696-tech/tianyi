> 日期：2026-10-24 ｜ 目标：把 `tianfu 1.2.36`、`daotu 1.5.2`、`shenshang`（神之商店）合并为单体模组 `tianyi`

## 1. 转世注入：两个 mixin 落在同一方法

**结论：两者都注入 `JingJieBaoCunProcedure.execute` 的 `HEAD`（不是 TAIL），方法描述符完全相同，且都幂等、互不读对方状态 —— 顺序无关，可安全合并为一个。**

| 项 | tianfu | daotu |
|---|---|---|
| 目标方法 | `execute(Lnet/neoforged/bus/api/Event;Lnet/minecraft/world/level/LevelAccessor;Lnet/minecraft/world/entity/Entity;)V` | 同 |
| 注入点 | `@At("HEAD")`，`require = 0` | `@At("HEAD")`，`require = 0` |
| 前置门禁 | `!FUHUO` 且 `(!XIUWEI 或 shouyuan <= 0)` | 同（逐字相同） |
| 异常处理 | try-catch 静默 | try-catch 静默 |

### 1.1 tianfu 侧动作（`TianfuOpening` / `TianfuData` / `TianfuAttributes` / `TianfuLiupai` / `TianfuTalents`）

1. 读 `fly_granted`（必须在 wipe 前，否则回收飞行失效）
2. 读 `vfx` 开关快照（特效开关属于玩家习惯，不随转世重置）
3. `TianfuLiupai.revoke(player, oldTizhi)` —— 回收体质自带的无限时长流派 buff
4. `TianfuTalents.revokeEffects(player, Set.of())` —— 回收词条常驻药水
5. `TianfuData.wipeAll(player)` → 回写 vfx 开关
6. `TianfuAttributes.sync(player)`（必须在 wipe **之后**，否则按旧已购重挂一遍）
7. 回收 `mayfly`（仅当 fly_granted 且非创造/旁观）
8. `TianfuOpening.resetKaiqiao(player)` —— scoreboard `kaiqiao` 归零
9. 播报一条

### 1.2 daotu 侧动作（`DaotuOpening.onReincarnation`）

1. 读 `run/ledger` 快照（必须在删树前）
2. 按快照 `subDaohen` 扣回道痕（下限 0，也必须在删树前）
3. `DaotuData.wipeAll(player)`
4. `DaotuRun.beginRun(player, oldId + 1)`
5. 回写 `autoPrompt` 与 `mainDao`（跨世保留项）
6. `DaotuData.markApplied(player)`
7. `DaotuAttributes.sync(player)`
8. 播报一条

### 1.3 合并后的唯一入口 `TianyiRebirth.settle(ServerPlayer)`

顺序（写死，不依赖 mixin 顺序）：

```
① 快照：oldTizhi / fly_granted / vfx / autoPrompt / mainDao / daotu ledger / oldDraws
② 扣道痕（按 daotu 账本，下限 0）
③ 回收实体侧：TianfuLiupai.revoke(oldTizhi) → TianfuTalents.revokeEffects(空集)
④ wipe：open 根、path 根、quest 根（天机点与 lifetime 不 wipe，见 §7）
⑤ 重建：DaotuRun.beginRun(oldId+1) → 回写 autoPrompt/mainDao → vfx 开关 → markApplied
⑥ TianyiAttributes.sync(player)   ← 单链，替代原来的两次 sync
⑦ 回收飞行（fly_granted 条件不变）
⑧ resetKaiqiao
⑨ 单条播报（三方文案合并为一行，避免刷三行）
```

**合并收益**：原来转世要跑两次属性重建、发三条消息；现在一次。

## 2. AttributeModifier 清单（双算点已定位）

**结论：两边都用 transient modifier（不写玩家 NBT，登录/结算幂等重建），因此改 id 前缀不破坏存档；但两边在 6 个属性上重叠，合并后必须每个属性只留一条本模组 modifier。**

| 属性 | tianfu id（ns `tianfu`） | daotu id（ns `daotu`） | 重叠 |
|---|---|---|---|
| `MAX_HEALTH` | `body_health_mult` (MULT_TOTAL) | `run_max_health` (MULT_TOTAL) | **是** |
| `ATTACK_DAMAGE` | `body_attack_mult` (MULT_TOTAL) | `run_attack_damage` (MULT_TOTAL) | **是** |
| `MOVEMENT_SPEED` | `body_speed_mult` (MULT_TOTAL) | `run_movement_speed` (MULT_TOTAL) | **是** |
| `ATTACK_SPEED` | `talent_attack_speed_mult` (MULT_TOTAL) | `run_attack_speed` (MULT_TOTAL) | **是** |
| `KNOCKBACK_RESISTANCE` | `talent_knockback_flat` (ADD_VALUE) | `run_knockback_resistance` (ADD_VALUE) | **是** |
| `SAFE_FALL_DISTANCE` | `talent_fall_flat` (ADD_VALUE) | `run_safe_fall_distance` (ADD_VALUE) | **是** |
| `JUMP_STRENGTH` | `talent_jump_flat` (ADD_VALUE) | — | 否 |
| `ARMOR_TOUGHNESS` / `MAX_ABSORPTION` / `FALL_DAMAGE_MULTIPLIER` / `LUCK` / `ATTACK_KNOCKBACK` / `OXYGEN_BONUS` / `STEP_HEIGHT` / `SCALE` | — | `run_<key>` 共 8 项 | 否 |

**共同红线（两边都刻意避开，必须继承）**：绝不碰 `Attributes.ARMOR`。本体有 46 个 procedure 用 `/attribute ... generic.armor base set N` 控护甲，modifier 会与本体蛊虫叠加，出现「卸甲后加成仍在」。

**合并裁决**：统一命名空间为 `tianyi`，但**保留两个来源各自的 modifier id**
（`tianyi:body_*` / `tianyi:talent_*` 与 `tianyi:run_*`）。

> **为什么不合成一条**：两路是<b>不同来源</b>的加成（体质/词条 vs 抽选），叠加是设计本意；
> 而撤销购买、转世回滚都要能<b>单独移除某一源</b>。合成一条 id 会让「只退掉天命那部分」
> 变成不可能，反而更危险。
>
> 真正需要守住的是：① 两路都用 transient（不落盘，登录/结算幂等重建）；
> ② 绝不碰 `Attributes.ARMOR`；③ 每路内部键不重复。
> 这三条由 `_pack/audit_attrs.py` 静态锁死。

## 3. shenshang 的 Attachment 与注册 id

**结论：全模组只有 1 个 AttachmentType，且必须保持 id 不变，否则玩家「元老蛊绑定」丢失。**

| 注册命名空间 | `shenshang` | **保持不变** |

## 6. 注册命名空间保留策略（决定）

| 层 | 是否改名 | 理由 |
|---|---|---|
| modid / Java 包 | **改** → `tianyi` / `net.guzhenren.tianyi.*` | 合并的身份 |
| 物品 id / mob effect id / 粒子 id / Attachment id / 数据标签路径 | **不改** | 改名 = 旧存档物品变未知物品、绑定丢失、常驻 buff 掉图标 |
| AttributeModifier id | **改** → `tianyi:attr/*` | transient，不落盘，改名无损 |
| 网络通道 | **改** → `tianyi:*`，单 registrar `"1"` | 合并后只有一个 mod，不存在混端 |
| 类名 | **不改**（保留 `TianfuXxx` / `DaotuXxx` / `ShopXxx`） | 只改 `package` 与 `MODID` 常量，把 diff 面压到最小，审计脚本可按前缀定位来源模块 |

由此产生一条代码约束：原 tianfu 用 `ModList.get().isLoaded("guzhenren_addon")` 之类判断「附属没装就隐藏」的逻辑，合并后语义变了。改为在 `FMLCommonSetupEvent`（注册表已冻结）求值的 `static boolean`，**不得**在 `static final` 初始化期查注册表（`TianfuPool.ENTRIES` 是 `static final`，类加载期查不到会把条目永久隐藏）。

## 7. 跨世保留项（合并后统一口径）

| 数据 | 转世 | 理由 |
|---|---|---|
| `open`（难度/点数/已购/已确认） | **清零** | 天命本世结算 |
| `path`（历练/抽选/历史） | **清零**，`runId + 1` | 道途本世结算 |
| `quest`（试炼进度/已领） | **清零** | 试炼是过程，不是资产 |
| `shop/tianji`（天机点） | **保留** | 天意是「系统」，跨世累积才有系统感 |
| `lifetime`（终身统计） | **保留** | 榜单数据源 |
| 签到连签 / 摇命保底 | **清零** | 防跨世攒保底 |
| `vfx` 开关 / `autoPrompt` / `mainDao` | **保留** | 玩家偏好 |

## 9. 勘验结论

- 转世注入可安全合并为单入口，且能去掉一次重复的属性重建与两条重复播报。
- 属性双算集中在 6 个属性上，改 id 前缀无存档风险，合并后每属性单条 modifier。
- shenshang 的存档耦合面极小（1 个 Attachment + 2 个物品 + 5 个 tag 文件），保留命名空间即可无损迁移。
- tianfu 的注册面（18 效果 + 6 粒子）同样可原样保留。
- **P1 可以开工。**
