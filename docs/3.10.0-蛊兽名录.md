## 二、阶数怎么定（重要）

本体**没有**妖兽等级字段（全库扫 `yaoshou / beast / dengji / jibie` 零命中），
`MAX_HEALTH` 也不能代表强弱：

```
魂兽（hunshou_1）        = 1000 血
魂兽·万兽王（hunshou_4）  = 1000 血   ← 同一档
木魅树精（_1）           = 760 血
木魅树精-兽皇（_5）       = 760 血   ← 也同一档
```

知识库里「不过万 / 不过十万 / 不过百万」是另一套口径，与本体的血条数值对不上，
硬套会把兽皇判成杂兵。**所以阶数只认名录**：

| 阶 | 含义 | 数量 |
|---|---|---|
| 1 | 特殊种（无规模分级） | 18 |
| 2 | 百兽 | 17 |
| 3 | 千兽 | 17 |
| 4 | 万兽 | 17 |
| 5 | 兽皇 | 16 |

名录里没有的本体妖兽仍按 1 阶处理（宁可当杂兵，也不凭空拔高）。

## 三、接到哪里

| 位置 | 变化 |
|---|---|
| `will/BeastCatalog`（新） | 纯数据表：id / 中文名 / 阶 / 流派，**不 import 任何 Minecraft 类型**，可离线测试 |
| `TianyiBestiary` | 阶数、阶名、流派全部改为委托名录，自己只保留 MC 侧判定（`isBeast` / `factionOf`） |
| `WorldExec.BEAST_POOL` | 从「写死两只」改为名录 **1–2 阶**派生 |
| `WorldExec.BEAST_ELITE` | 从名录 **3–5 阶**派生 |
| `BeastHerds.BASE_BEASTS` / `ELITE_BEASTS` | 同上，兽群不再只有魂兽和树精 |
| `BeastHerds.recordKill` | 物种核验改为「同种 或 在本名录里」，不再靠两张小数组 |
| `TianyiBestiary.daoOf` / `nameOf`（新） | 供日志、身份案、册子文案用 |

```
名录 85 条，全部在本体 jar 中存在
名字与本体一致（忽略「·」「.」「-」写法差异）
带「百兽王/千兽王/万兽王/兽皇」的名字，阶数分别为 2/3/4/5
```

- 新增测试 `BeastCatalogTest`（56 项）：id 唯一且全是 `guzhenren:` 命名空间、
  阶数合法、每阶有货、流派抽样正确（豪电狼→雷道、虎→金道、刻纹蛇→宙道…）、
  查询接口与数据一致、阶名正确。
- `audit_bestiary.py` 重写：从「只看两族 5 只」改为「对全名录 85 条逐个核对本体 lang 表」，
  并新增「档位词 ↔ 阶数」一致性检查。

## 五、边界与未做

1. **没有实机验证**：这些 id 全部存在于本体 jar，但「在什么群系/地形刷」由本体决定，
   本模组只负责**引用**它们，不改本体刷怪规则。
2. **地牢变体未收录**：`dilaoleiguantoulang`（雷冠头狼·地牢）、`liaoyuanhuoxiongdilao`
   等同名地牢版没有单独登记，避免与野外版混为一谈。
3. **幻象变体未收录**：`huli_4huanxiang` / `huli_5huangxiang` 是幻象实体，不是独立种族。
4. **知识库特殊种里缺 3 个 id**：土犬、水羚羊、澜风隼在本体 lang 表里没找到对应实体，
   因此**没有**写进名录 —— 不编造 id。
5. **奇遇系统仍用自己的 6 只表**：`encounter/EncounterBeasts` 是另一条线新建的子系统的
   独立名单，本轮没有改动它；后续应改为读 `BeastCatalog`，否则两处名单会不一致。
