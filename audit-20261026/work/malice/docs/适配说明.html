一、它到底改了什么东西

只做两件事，一行本体代码都没碰：

  1. 数据驱动接入：data/guzhenren/l2hostility_config/entity/guzhenren_malice.json 给三档妖兽各自的等级下限、血量/攻击倍率、词条白名单与黑名单。
  2. 难度倍率：等恶意把等级算完（HostilityInitEvent.Post），按玩家选的档位再乘一次等级，并补满血。
强度全部来自恶意自己的等级公式（每级 +3% 血、+2% 伤害，命中时再按 attackScale 放大）。所以卸载本 mod，存档立刻回到「只有恶意」的原状，不会有属性残留。
为什么不直接抬本体血量？本体妖兽的基础血已经是 760~1024、攻击 65~200，再乘倍率会出现「怪打不死、玩家也没法打」的硬墙；用恶意等级做放大可以随难度档位和玩家等级一起浮动。

一·五、为什么妖兽头顶原来没有等级

恶意 3.0.18 决定要不要给一只生物挂 MobTraitCap 的条件写死在 LHMiscs 里：

isProper(e) = e.getType().is(l2hostility:whitelist)
           || (e instanceof net.minecraft.world.entity.monster.Enemy
               && !e.getType().is(l2hostility:blacklist))

本体 450 个实体里只有 7 个继承 Monster（也就是 Enemy），其余妖兽全是 TamableAnimal / PathfinderMob。它们既不在白名单、又不是 Enemy，所以恶意根本不挂能力 —— 不分配等级、不抽词条、头顶什么都不显示。这跟有没有装适配 mod 无关。

1.0.1 的修法：把 91 只妖兽写进 data/l2hostility/tags/entity_type/whitelist.json。标签是合并的（replace: false），不会覆盖恶意自己或其它模组写进去的条目。

怎么确认生效：① 进世界看日志里的 数据检查: 普通=23 精英=55 妖王=13 … l2hostility:whitelist=91；② 新刷出的妖兽头顶应有 Lv.N；③ /guzhenren_malice probe <实体> 直接读恶意的血量修饰符。

实际血量加成 = 等级 × 0.03 × healthScale；攻击放大 = 等级 × 0.02 × attackScale（命中时结算）。

已禁用词条：适应（adaptive）、升空（levitation） —— 两处同时生效：① 恶意全局配置 config/l2configs/l2hostility-server.toml 里 allow_adaptive = false / allow_levitation = false（对原版怪也生效）；② 本 mod 三档配置的 blacklist 里也写了这两个 id，并从精英档保底词条里删掉「适应」。全局开关只管随机抽取，保底词条是配置直接给的，所以两边都要写。

四·五、显示调整：词条挤成一坨

恶意的名字牌是一次性画的一整块文字：等级和所有词条拼在同一个组件里。一只妖王 8 个词条就会横着拉出一大条，几只怪凑一起就糊成一片、把怪本身盖住。

调的不是词条数量（那会削弱强度），而是显示位置：showTraitOverHead = false —— 头顶只留 Lv.N，词条不再堆在怪身上。

词条没有消失：Jade 的实体面板会列出这只怪的全部词条（恶意自带 TraitInfo 兼容），准星指过去就看得到。

想要「平时不显示、瞄准谁就显示谁」，改成 showTraitOverHead = true + showOnlyWhenHovered = true 即可。

同款配置已复制到 defaultconfigs/l2configs/l2hostility-client.toml，重置 config 也不会丢。

1.0.3 审查修复：恶意的 HostilityInitEvent.Post 在 init() / tick() / copyFrom() 三处各发一次，每只怪至少收到两次 —— 旧版每次都乘倍率，凶险档 Lv20 会变成 20→30→45、噩梦档 20→44→97。现在把「恶意原始等级」记进实体 PersistentData，重复回调变成空操作。详见 docs/审查记录.md。
