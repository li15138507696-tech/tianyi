# 3.1.0 情报与布局：玩法与迁移说明

> 本期落地的是「一期」：**本体桥接 + 世界事实 + 情报传播 + 天意接线 + 一组 NPC 调查/追捕**。
> 二期（资源点 / 物流 / 寿蛊 / 兽群）与三期（身份证据链 / 意志载体反侦察 / 炼道传承联动）
> 的清单在文末「尚未完成」里逐条列明，没有写成已完成。

## 一、玩家能感知到什么

天意仍然**不可见**：没有好感度、没有威胁评分、没有干预列表、没有面板。
本期新增的感受只有三种，全部通过世界本身表现：

1. **你说的话会传出去。** 你在野外采走了蛊材，附近的 NPC 会看见；
   看见的 NPC 会把这件事告诉别人，传递有距离、有延迟、也会断（人死了、离开这一带就断了）。
2. **远处的人真的不知道。** 没有目击者、也没有人给他带话的 NPC，
   **不会**来调查你，也**不会**知道你在哪 —— 这不是「概率低」，是根本没有那条情报。
3. **有人上门。** 知道你做了什么、且离得最近的 NPC 会来调查；抢夺或杀人则会招来追捕。
   来的人有名字、有状态、会写生活日志、也会记仇。

## 二、机制细节（面向整合包作者与 OP）

### 情报的三层结构

| 层 | 类 | 作用 |
|---|---|---|
| 事实 | `fact.WorldFact` | 世界上真实发生过的一件事：谁、在哪、什么时候、做了什么、多可信、多久过期 |
| 总账 | `fact.FactLedger` | 去重（同一件事按「行为+行为人+目标+位置+时间桶」只存一条）、过期清理 |
| 网络 | `fact.IntelNet` | 谁知道了哪条事实、从谁那里听来的、传了几手、还剩多少可信度 |

- 传播只在**居民之间**发生，边来自「同维度 + 距离 ≤ `WillConfig.CARRIER_REACH`」，
  走一条边可信度 × 0.8，最多 3 跳，每跳有 200 刻延迟。
- 事实按 `baseConfidence × 时间衰减` 判定；低于 `WillConfig.CONFIDENCE_ACT_FLOOR`（0.35）
  的传闻不会变成行动。
- **身份用完整 UUID，不用名字**：切换身份不会抹掉已经写下的证据，
  因为证据从一开始就记在「当时那个身份」的 UUID 上。

### 行动的产生与失败

```
事实 → 谁能看到（居民目击） → 传开 → 知道的人里挑最近的当执行者
     → 排入布局队列（同动作+同目标+同一分钟只排一次）
     → 到点执行（每 tick 最多 ACTIVE_JOBS_PER_TICK 条）
```

每一步的结局都记在 `action.ActResult` 的五种状态里：

| 状态 | 含义 | 对后续的影响 |
|---|---|---|
| `OK` | 真的动了世界 | 该步结束 |
| `DENIED` | 条件不成立（人已死、势力没了） | 直接放弃，不再骚扰 |
| `BLOCKED` | **渠道被切断**（载体被清、观测断开、商队被截） | 冷却 9600 刻，之后可再试；连试 4 次放弃 |
| `FAILED` | 动手了但本体侧失败 | 冷却 2400 刻 |
| `DEFERRED` | 时机未到 | 不消耗重试次数 |

`BLOCKED` 是关键：**玩家切断渠道，天意的这一步就真的走不下去**，只能换个方式重来。

## 三、存档迁移

- **不删任何旧数据。** 旧存档里的修为、蛊虫、关系、势力、居民、商队全部保留。
- 新增一份独立的 SavedData `tianyi_intel`（`world/IntelState`），根节点带
  `schemaVersion`（当前 `1`）。旧存档第一次加载时该文件不存在，会按空数据初始化。
- 读取时若 `schemaVersion` 缺失或偏旧：**只读不删**，读不出来的条目跳过，版本号补到当前值。
  不存在「清档重来」的分支。
- 写档 `schemaVersion` 取 `max(当前版本, 读到的版本)`，所以降级回旧版也不会丢字段。

## 四、依赖与环境

- **新增硬依赖 `guzhenren_library`**（本体自带的势力/NPC/任务/身份扩展层）。
  `neoforge.mods.toml` 已声明 `type = "required"`。只有内层 `guzhenren` 的实例会加载失败 ——
  这是有意的：桥接层没有它就没有任何可调用的对象，静默降级比直接报错更难查。
- 仍然**零 Mixin**。`_pack/verify_jar.py` 会强制检查 jar 里没有 mixin 配置、没有 mixin 类、
  也没有把本体打成 jar-in-jar。

## 七、3.1.1：寿蛊来源审计与自然供给

### 为什么单独做这一条

3.0.0 的 `Immortal.LifespanSupply` 只是纯逻辑模型，**游戏里从未被调用** ——
「天意通过未来供给制约长生」当时是空话。这一版把它接到世界里。

### 寿蛊的全部来源

| 来源 | 谁负责 | 本模组是否干预 |
|---|---|---|
| 自然演化（野外成蛊） | **本模组** `world/ShouGuSupply` | 只改周期与数量，**不改库存** |
| NPC 库存补货 | 本体 `NpcStock.restock(Mob)` | **不干预**（只清点 ID）。接管它会造成双重补货，所以刻意不做 |
| 存量 / 传承 / 交易 | 本体与整合包既有流程 | **不干预** |
| 炼制 | 本体炼蛊流程 | **不干预**（原著未给炼制法） |

### 白名单从哪来（不是我们编的）

`NpcStock.longevityIds()` —— **本体自己认定属于寿蛊的那些注册 ID**，
经 `bridge/GuzhenrenBridge.longevityIds()` 读出后灌进 `LifespanSupply.audit(...)`。

- 白名单**为空时一颗都不生成**（桥接层不可用就这一轮空着，绝不发错东西）；
- `pick()` 只从白名单里挑，`allowed()` 大小写不敏感；
- 只接受**完整注册 ID**（含命名空间），裸名字被拒 —— 与全项目身份规范一致。

### 落在世界里的样子

到周期（`SHOU_GU_SUPPLY_PERIOD`，30 游戏日）就在已加载区块的地表成蛊：
距玩家 32–96 格、走自然掉落、**谁捡到算谁的**，掉落物带 `tianyi_shougu` 标记便于审计。
歉收期（速率 < 0.4）可能这一轮一颗都不成 —— 不是「取消掉落」，是本来就没成蛊。

### 验证

- `WillCoreTest#testShouGuSourceAudit`：10 项断言（白名单过滤、空集不产出、
  大小写、重新审计覆盖、审计后仍不碰库存）；
- `_pack/audit_will.py`：`LifespanSupply` 里不得出现 remove/take/deduct/consume；
- `/tianyi shougu`（OP）可直接查看清点结果。

### 仍未做

- **物流 `CargoBatch`**：本体没有货物批次概念，需要自建，仍未做；
- **野生兽群**：栖息地与种群账目未做。

## 八、3.2.0：资源产地

### 为什么从「一次掉落」改成「一处产地」

3.0.0 的扶持只是在地表丢一次物品：拿完就没了，也没法被天意针对 ——
没有「资源点」这个对象可以毁。原著里天意剿不掉目标时会「借天道改易道痕的权限把资源点搅烂」，
**要能毁，先得有个东西可毁**。

### 五本账

| 账 | 字段 | 规则 |
|---|---|---|
| 储量 | `stock` / `maxStock` | 有上限；新发现的产地只有六成 |
| 恢复 | `regenPerDay` | 按游戏日回补；**毁了就不再回** |
| 上限 | `maxStock` | 恢复封顶，不会无限长 |
| 归属 | `owner` | 第一个来采的人占下；别人再来算「掠夺」，记 `poached` |
| 破坏 | `destroy` / `scramble` | 天意搅乱道痕（储量打散、恢复变慢）或玩家采尽（变荒） |

**最硬的一条：不可能刷物品。** `harvest` 的返回值被夹在
`Math.min(floor(stock), want)` 以内，所以吐出来的总数永远 ≤ 初始储量 + 期间恢复量。
测试里跑了 50 轮「恢复→采集」并断言这条守恒。

### 世界里怎么表现

- 扶持渠道（`RESOURCE` / `HERITAGE`）现在**开一处产地**，而不是丢一次货；
- 产地每 2400 刻检查一次：半径内有玩家才出货（**没人靠近就不产**，储量攒到上限），
  货落在地上、带 `tianyi_site` 标记，谁捡到算谁的；
- 天意压制目标时走 `RESOURCE` 渠道会**优先搅乱目标名下的产地**，
  没有产地才退回扰动仙窍资源账；
- 诱饵产地（`bait`）第一批货被捡走时触发「道破即震怒」的局部雷雨，且**只怒一次**。

### 可调查性

每处产地都带 `lastCause`：`natural` / `claimed` / `poached-by:<uuid>` /
`exhausted` / `will:daohen_scramble` / `reassigned` / 显式的破坏原因。
`/tianyi sites`（OP）直接列全部产地的储量、恢复、归属与原因。

### 持久化与重启

产地写进 `WillState` 的 `sites` 列表（储量、恢复、归属、状态、原因、产出/掠夺计数、诱饵标记）。
未知枚举值跳过而不阻断加载 —— 跨版本旧档也能读。

### 仍未做

- 产地的**空间扩散**（目前一处产地只覆盖半径 24 格的单点）；
- 与本体势力地盘（`FactionTerritory`）的归属联动 —— 现在归属是玩家 UUID，
  还没有「这块地属于哪个势力」的对接。

## 九、3.3.0：物流批次与幂等结算

### 为什么要有「运输」这一段

产地如果直接把货刷在玩家脚下，就没有路线、没有护送、也没有可被切断的环节，
天意也就失去了「断人之货」这条手段。批次把**产出**和**到手**拆开：
货从产地预留出来，走一段路，到点才结算。

### 三种结局，都必须留痕

| 结局 | 触发 | 货去哪 |
|---|---|---|
| `DELIVERED` | 到点、收货人在线 | 落到收货人脚下 |
| `BLOCKED` | 到点时收货人不在（路线断） | **退回起运产地**（受储量上限约束，不吞不吞） |
| `LOST` | 被劫（`lose`） | 归劫货者 |

### 幂等结算（本版最重要的一条）

`CargoBatch.settle` 的闸门是 `state != IN_TRANSIT || !arrived(now)` → 直接返回空；
`Book.tick` 在发货前还会再查一次**结算簿** `settled`。
结算簿写进 `WillState` 的 `cargoSettled`，所以：

> 玩家在结算瞬间重连 **或** 服务器在结算前后重启，**都不会发两遍货**。

测试里专门做了「重启模拟」：新建一个簿子、只灌结算簿，再 tick 一次 —— 断言发货为空。

### 世界里的流转

- 产地出货时，如果产地有归属、且归属人不是眼前的「路人」，就开一批
  `cargo-<产地>-<时刻>`，运输 2400 刻；
- 到点由 `WorldSites.deliver` 结算，货落到归属人脚下；
- 收货人不在 → 货退回原产地（`returnStock`，受 `maxStock` 约束，
  所以「发出去再退回」不可能突破上限刷货）。

### 仍未做

- **护送与劫掠的实体表现**：现在 `lose` 只有 API 与测试，世界里还没有可被劫的车队实体；
- 路线上的**地理校验**（穿墙运输不检查地形）；
- 与势力（`FactionBrain`）的商队联动。

## 十、3.4.0：野生兽群

### 要解决的老毛病

3.0.0 的「兽群」是按数量直接生成一批实体 —— 那不是生态，是刷怪点。
现在的顺序反过来：**先有种群，才能生成**。

### 生态账

| 项 | 规则 |
|---|---|
| 种群 `population` | 这个兽群真正有多少只；**生成一只就少一只** |
| 承载力 `capacity` | 栖息地能养多少；增长朝它靠拢，越满越慢 |
| 栖息地质量 | 0.25~1.0（按地表可站立 + 附近是否临水粗算） |
| 猎杀 | 杀掉带 `tianyi_herd` 标记的兽 → 种群真的减少 |
| 崩溃 | 种群见底变 `COLLAPSED`，**不再繁殖、也赶不出兽** |
| 迁徙 | 栖息地 < 0.35 或种群 > 85% 承载力 → 锚点真的挪走（记 `migrations`、`lastCause`） |

### 天意怎么用（这是关键）

`BeastHerds.driveToward` 只能从**最近的、还有兽的兽群**里 `drive` 出兽，
且 `drive` 的返回值夹在 `floor(population)` 以内。所以：

> 天意不能凭空变出兽潮，它只能把**已经存在的兽**往某人那边赶。

这正是原著里天意「影响他人成为劫」的分寸：借势，不造兵。

### 崩溃与恢复

种群见底后兽群进 `COLLAPSED`，`grow` 直接返回 0（不繁殖），`drive` 也返回 0。
要恢复只能等栖息地变好并重新建群 —— 这是对「以前无限刷怪」最直接的反制。

### 仍未做

- **兽群与地形/生物群系的真实联动**：栖息地质量目前只按「临水」粗算，
  没有读生物群系标签；
- **兽群之间的竞争**（两个兽群抢同一片栖息地）；
- 兽群与玩家势力地盘（`FactionTerritory`）的冲突判定。

## 十一、3.5.0：炼蛊证据的判定规则

### 为什么「看进度」是错的

本体把炼蛊进度放在 `PlayerVariables.LianGuJinDu`（0~100）。只判断「是不是 100」
会踩三个坑，每一个都会让「炼蛊证据」变成假证据：

| 坑 | 后果 |
|---|---|
| 满值滞留 | 炼成后进度停在 100，每轮都读一次 → 一次炼蛊被记成无数次 |
| 浮点近似 | `99.999` / `100.0001` 被 `>= 100` 判成完成 |
| 没有产物 | 记不出「炼出了什么」，这种证据没用 |

### 三条同时成立的判据

1. 进度**恰好等于** `100.0`（`AlchemyTracker.COMPLETE`，精确相等，**不是** `>=`）；
2. 观测器**见过它在 100 以下**（`seenBelow`）—— 证明确实有一次从不足到完成的过程；
3. 有可识别的产物（完整注册 ID）且数量 > 0。

完成一次立刻复位 `seenBelow`，所以「停在 100」不会再计数。

### 验证

`WillCoreTest#testAlchemyEvidenceBinding` 20 项断言，反证：99.9 不算、
`100.0001` 不算、停在 100 只算一次、无产物不算、裸名字产物不算、数量 0 不算、
第二次真的重炼能再算一次。审计另加静态锁：`COMPLETE = 100.0` 必须在，
且**禁止出现 `progress >= COMPLETE`**。

### 未接线的部分（必须说清楚）

**世界侧还没有把这条规则接上。** 本体 `PlayerVariables` 只暴露
`LianGuJinDu` / `LianGu` / `GuFang`，**没有任何字段能读到「这次炼出了什么」**。
没有产物 ID 就凑不齐第 3 条判据，硬接只会产出「炼成过但不知道炼出什么」的假证据。

所以现状是：**判定规则完整、可测试、有审计**；**证据产出为空**。
等确认到能拿到产物 ID 的接口（或改用炼蛊相关事件）再接世界侧。

## 十三、3.7.0：炼蛊证据的世界侧接线（背包差异推断）

### 本体不说的那件事，用差异补上

经过两轮核查（`guzhenren_library` 与内层本体都没有 alchemy/product 接口），
确认**没有任何字段能读到「这次炼出了什么」**。所以改成：

```
进度 < 100 → 给背包拍个基线快照（只数 guzhenren: 命名空间的物品）
进度恰好 100 → 与基线比对，取「新增最多」的那一项当产物
```

### 三条纪律（每条都有测试与静态锁）

1. **只认数量增加的差异**：减少的键一律不算（那是消耗，不是产物）；
2. **只认完整注册 ID**：裸名字直接忽略，避免把脏数据当产物；
3. **挑不出产物就不记证据**：宁可漏记一次，也不写一条「不知道炼出什么」的假证据。

### 证据落到哪

- 知识库：`Knowledge.Kind.CRAFT` 一条事实（带产物数量、维度、坐标、时间）；
- 身份案：一条 `CRAFT_TRACE` 证据（权重随产物数量涨，可靠度 0.85），
  与前两轮的 `WITNESS` / 其它证据**互证**；攒到双门槛就能识破身份；
- 满值滞留不会重复：只看 `seenBelow` 与精确 `100.0`，完成后即复位；
- 进度归零（这一轮结束/失败）会清掉基线，下次重新拍。

### 验证

- `WillCoreTest#testAlchemyProductInference`：15 项断言（只认增加、减少不算、
  裸名字忽略、挑最大增量、并列结果稳定、空差异返回 null、端到端产物推断）；
- 审计静态锁：`AlchemyWitness` 必须用 `diff(baseline, current)` 与 `topProduct`、
  必须限定 `guzhenren` 命名空间、挑不出产物必须退成空串；
- 只读例外的处理：`AlchemyWitness` 是**唯一**允许读 `getInventory().items` 的
  世界侧文件，审计里按白名单放行，同时额外禁止它写背包（`setItem`/`setCount`）。

### 这条路的边界（必须知道）

- **推断会漏**：如果炼成后玩家立刻把产物放进箱子/丢弃/联机转移，
  差异里就看不到，这次炼成会**漏记**（不会错记）；
- **推断可能不准**：同一轮里如果恰好又捡到了别的本体物品，
  增量最大的那一项可能不是真产物；
- 这两条都是「推断」的固有限制，不是实现缺陷 —— 要彻底解决只能等本体暴露产物接口。

## 十二、3.6.0：身份证据链与载体统一状态

### 身份证据链（`will/IdentityCase`）

三条不可动摇的规矩：

1. **证据记在当时的那个身份上。** 每条证据都绑在「事发那一刻的完整 UUID」，
   改名/换皮/换势力都不会改写已经写下的记录；
2. **单条弱证据不构成识破。** 判识破要**双门槛**：
   可信度 ≥ `IDENTIFY_AT`(6.0) **且** 至少 `MIN_KINDS`(3) 类**不同**证据；
3. **矛盾不会被抹掉。** 指向另一种身份的证词会压低结论可信度（`contradictedScore`），
   但原始记录一律保留 —— 所以「谁在撒谎」可追溯。

另外防了「刷同一句流言」：同一 `Kind` 只取权重最高的一条进主分，
其余按 `DUPLICATE_FACTOR`(0.25) 折价 —— 十句传闻 ≠ 十个证据。

世界侧接线：**有载体看着**的当众杀戮会写一条 `WITNESS` 证据进身份案
（`/tianyi identity` 可查判定、可信度、类别数、矛盾分）。证据链持久化在 `WillState.identity`。

### 载体统一状态（`Carrier.State`）

把「寄存 → 传播 → 消耗 → 清除 → 恢复」收敛成**一个**状态机，
不再让各处的判断各算一套：

| 状态 | 判定 |
|---|---|
| `PURGED` | 仍在盲区（被天消意散/炼道清掉） |
| `REGROWING` | 过了盲区、正在渗回来（`regrowTicks > 0` 且完整度 < 0.6） |
| `ACTIVE` | 完整度 ≥ 0.6 |
| `DORMANT` | 0.2 ~ 0.6 |
| `DRAINED` | < 0.2（被反复消耗，没被清但没力气了） |

- 唯一判定入口 `Node.state(now)`；`canHost(now)` 只在 `ACTIVE`/`REGROWING` 为真；
- 世界级状态 `Network.worldState(now)` 取「最强那处」，所以不会出现
  「按载体看是活的、按区域盲区看是死的」这种自相矛盾；
- 渗满（完整度回到 0.6）时把恢复计时清零，否则载体会永远卡在 `REGROWING`。

### 验证

- `WillCoreTest#testIdentityEvidenceChain`：19 项断言（单条不足、三类识破、
  重复拒收、十句流言不构成识破、矛盾压低但保留、拒收他人 UUID 的证据、案件簿计数）；
- `WillCoreTest#testCarrierUnifiedState`：17 项断言（活跃→枯竭→已清除→恢复中→回活跃、
  恢复计时清零、世界状态取最强、状态计数自洽）；
- 审计静态锁：识破必须双门槛、证据必须绑 UUID、必须有 `contradictedScore`；
  载体必须有 `enum State` 与唯一 `state()` 入口。

### 仍未做

- 身份证据目前只来自「当众杀戮」一个来源；**证词、持有物、炼蛊痕迹、关系线索**
  四类虽已在 `Kind` 里定义，但世界侧还没有采集路径；
- 身份识破还没有反过来影响天意的决策（识破后应当能更精准地布局）——
  这需要把 `IdentityCase.verdict()` 接进 `Assessment`，本轮没做。
