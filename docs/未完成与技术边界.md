不等于「在服务器里跑过且表现正确」。以下是进游戏后最可能先出问题的地方：

1. `Observation` 用反射读 `PlayerVariables` 的 28 个 `daohen_*` 字段拼实力。
   字段名一旦随本体版本改名，反射取不到 **不会报错**，只会按 0 处理 → 实力被低估。
   这是有意的降级（不猜语义），但会造成「天意看不见道痕」的静默偏差。
2. 实力 = `1 + 转数 + Σ道痕×0.02 + 攻击×0.01` 是**平衡启发式**，没有任何原著依据；
   份额阈值（0.38）与威胁下限（0.55）都是拍出来的，实测后极可能要调。
3. 生成点只用 `WORLD_SURFACE` 高度图 + `isLoaded` 判定。洞穴世界、虚空维度、
   水面上会生成在半空中或水面上 —— 未处理。
4. 人劫 NPC 用 `setTarget(player)` + `setPersistenceRequired()`，**没有**接
   `guzhenren_library` 的对话/关系系统；这些修士上门后是否会真的打起来，
   取决于本体 AI，未实测。
5. 灾劫的「世界效果」目前只有：雷雨天气、闪电实体、妖兽显形、烟雾粒子、
   以及结算时的伤害与道痕。**没有**地貌改写（万劫的 `env:terrain_rewrite` 只是一个效果键，
   `CalamityRunner` 尚未按它改方块）。

## 二、原著能力里没有实现的

| 能力（考据编号） | 为什么没做 |
|---|---|
| **2 侵蚀并"制造"仙元石** | 需要在本体「仙窍产仙元」的流程里插入一步（人意被天意盖压 → 产物带天意，八转去天意后效用减半）。本体的仙元产出路径**没有核实到可挂钩的公共接口**，硬接会与本体流程重复结算。宁可不做。 |
| **6 催动他人仙蛊** | 需要访问「已炼化的仙蛊实例」并能触发它的杀招。本体仙蛊是物品 + 内部状态，未核实到公开的「催动」入口。 |
| **1 侵蚀仙蛊/器物（深度）** | 只做到载体层的完整度消耗与清除（`Carrier`）；没有对具体某一件仙蛊（如春秋蝉）做逐件侵蚀与裂纹状态。 |
| **9 与升仙者"对话"** | 只实现「师法自然累积 → 提高升仙成功率」的数学部分；没有一次真正的「对话窗口」事件。 |
| **11 灾劫分级细节** | 四等名称与相对规模按原著，但「多少转该渡哪一等」「道痕具体给多少」原著未量化，全部是 `WillConfig` 里的平衡参数。 |

### 关于「福地洞天 / 独立仙窍」

实现只到**判据层**：`Immortal.Aperture.willIntrusionPossible(independent, hasHeavenDaoMark)`。
即「独立仙窍 + 无天道道痕 → 天意管不了；有天道道痕 → 本地生天意」。

**没有**真的创建一个独立维度充当福地洞天。所以玩家目前无处可躲 ——
这个避风港在代码里成立，在世界里还不存在。

## 三、系统和接线的边界

| 项 | 现状 | 边界 |
|---|---|---|
| 客户端界面 | **完全没有** | 有意为之：天意必须隐性。代价是仙窍/灾劫没有任何可视化面板，只能靠 `/tianyi aperture` 看自己的数据 |
| 客户端同步链 | 已删除（`client/`、`net/`、payload） | 没有状态包，也就没有「天意好感」这类字段可供误用 |

| NPC 关系 / 对话 / 任务 | 未接入 | `guzhenren_library` 有 `NpcDialogueLibrary` / 关系系统 / `QuestGiver`，本次没有用 |
| 道德 | 只读 `daode`，只用于「社会代价」与「借人施劫」 | 没有挂钩本体的缉捕/声望事件，避免重复结算；本体自身的道德效果照旧 |
| 气运 | 只读 `qiyun` / `qiyun_shangxian`，只影响机缘酝酿时长 | 不把气运当善恶，也不做「气运高=天意偏爱」 |
| 调度 | 决策 200 刻/轮、推进 20 刻、清理 200 刻 | 单轮只处理 16 个参与者；**玩家超过 16 人时会轮不到**，没有做分区轮转的游标 |
| 数据规模 | 知识库每主体上限 24 条、总布局上限 6、机缘有 TTL | 长周期存档下 `WillState` 的 `settled` 键只增不减，未做清理 |

### 运行期状态哪些能过重启

`WillState`（`tianyi_will` SavedData）持久化的是：宿命阶段/修复任务进度（后者不代表宿命强度、
不驱动阶段）、星宿份额与胜负、
意志余量、姿态、叠加计数、冷却、知识库（含遮蔽）、载体网络与区域盲区、
每个玩家的仙窍、快照元数据、幂等结算键、增长基线。

**不持久化**的是：在飞的布局（`Ploy`）、进行中的灾劫（`Calamity.Run`）、
未成熟的机缘（`Opportunity.Offer`）。它们有两段的游戏刻生命周期，
服务端重启后直接消失、由下一轮决策重新生成。

这是一个取舍：这些对象带大量「此刻」语义（到期时刻、阶段进度、渲染键），
序列化它们要引入 schema 兼容与"重启后补算"的一整套逻辑，收益低于风险。
代价是**重启会让正在酝酿的人劫中断** —— 这一点必须知道，不能当成 bug 去查。

## 四、春秋蝉回溯的边界

| 项 | 现状 |
|---|---|
| 快照内容 | `level.dat` + `region` / `entities` / `poi` / `data` / `playerdata` / `dimensions` / `datapacks` |
| 快照时机 | **只在执行 `/tianyi snapshot` 时**生成。没有自动/滚动历史 |
| 可回溯节点 | 只有**已验证**的快照；`Store.latest()` 会跳过未验证的 |
| 恢复方式 | **两段式**：游戏内写标记 + 停机 → `_pack/rewind_apply.py` 交换文件 → 重启。**运行期不写回任何区块文件** |
| 完整性校验 | 每个分区 `relpath:sha256` 拼串再哈希；恢复前**按磁盘重算**并比对 |
| 失败恢复 | 交换前把当前世界整体备份到 `tianyi_rewind_backup_<ts>/`；交换中途失败会停下并提示从备份恢复（脚本不做自动回滚） |
| 分支标识 | 回溯生成 `main-r1`、`main-r2`… 新分支名，原分支只读保留；完成标记写在 `rewind_done_<branch>.json` |
| 时间精度 | **一次快照 = 一个可回溯点**。两个快照之间的任何时刻都回不去，这是硬边界，不假装 |
| 磁盘占用 | 每份快照≈整个世界的大小。没有做增量/差量，未做自动清理 |
| 物品复制 | `History.carriesInventory()` 恒 false；世界整体回到过去，玩家背包随世界一起回，**不会**额外多出一份 |
| 玩家记忆 | 无法抹除。这一点写在命令提示与 `RewindPlan.boundaryNotes` 里，是明确声明的不可还原边界 |
| 天意的未来记忆 | `History.willLearnsFromLogs()` 恒 false；只有通过春秋蝉参与才可能获得 |

### 未验证的环节

- `rewind_apply.py` 的摘要算法与 Java 侧**逐字对齐**（按 `rel` 顺序、文件路径排序、
  `relpath:sha256` 拼串后哈希），但**没有在真实存档上跑过一次完整交换**。
  首次使用时建议先 `--dry-run`。
- 停机用 `server.halt(false)` + 2 秒延迟；如果主线程卡在保存里，可能来不及关干净。
  这种情形下 `pending_rewind.json` 仍在，脚本会重新校验，不会盲目交换。

## 五、设计上刻意「不做」的

这些不是遗漏，是**按原著拒绝**的：

| 不做 | 原著依据 |
|---|---|
| 天意亲自出手直接杀人 | 原文里天意只通过棋子、人劫、灾劫、侵蚀载体、搅乱道痕起作用，没有直接击杀 |
| 给玩家看天意好感/威胁评分/干预清单 | 「天意从不看我们可怜来帮助我们」—— 它是压力源，不是保姆 |
| 任何手段「免疫天意」 | 神不知只防推算且九转智道可破；完整天外之魔只超脱宿命，第七章里资源照样被毁 |
| 天意按道德奖惩 | 「天意，从不是看我们不顺眼，也从不看我们可怜」 |
| 删除玩家背包里的寿蛊 | 天意制约长生走的是**未来供给**，不是后台删物品 |
| 一个 buff 统一挡掉所有反制 | 五种环节（感知/推算/载体/宿命约束/天道控制）必须逐项区分 |
| 混沌归天意支配 | `Calamity.chaosInfluenced()` 恒 false；混沌要单独考据 |

### 关于「另一条并行工作线」

先纠正一版错误结论。3.0.0 交付期间曾一度把 `action/`、`fact/`、`bridge/` 判为
「外部进程写入的重复架构」并移出源码树。**这个判断是错的**：用户提供了那次工作导出的归档
（`dsh-session-session-8b85fd5a…zip`），确认它是**同一个工程目录下的并行工作线**，
任务是在 3.0.0 之上做「3.1.0 一至五转世界补强」，并明确把 3.0.0 当基线。

因此：

- `action/`（行动队列与状态机）、`fact/`（世界事实与情报传播）、
  `bridge/GuzhenrenBridge`（本体 API 桥）**是正式实现的一部分，已并入本交付**；
- `guzhenren_library-api.jar` 的 697 条目已逐条核对与本体 jar 逐字节一致；
- 先前移走的副本仍在 `_backup/parallel-agent-staging-20261024-232024/`，
  但**当前源码树里的那份是正式版本**，不要再用备份覆盖。

两条工作线的分工：

| 层 | 归属 | 内容 |
|---|---|---|
| `will/` | 主线交付（3.0.0） | 世界意志纯逻辑：知识边界、评估、决策、布局、机缘、灾劫、仙道、宿命、载体、反制、回溯 |
| `world/`（WillState/WillServer/Observation/WorldExec/SnapshotService/LegacyRetire） | 主线交付（3.0.0） | 服务端权威调度、世界执行、快照 |

| `world/ShouGuSupply` + `Immortal.LifespanSupply.audit` | 主线交付（3.1.1） | 寿蛊来源审计与自然供给落地 |
