# 蛊真人 × 莱特兰恶意 · 适配附属 guzhenren_malice

> 版本 1.1.1 ｜ MC 1.21.1 / NeoForge 21.1.263 ｜ 依赖 guzhenren 0.1 + l2hostility 3.0.18

## 这个 mod 做什么

只做两件事，一行本体代码都没改：

1. **把本体妖兽接进恶意**：`data/guzhenren/l2hostility_config/entity/guzhenren_malice.json` 给三档妖兽各自的等级下限、血量/攻击倍率、词条白名单与黑名单。
2. **四档可切换难度**：恶意分完等级之后，按玩家选的档位再乘一次等级（`HostilityInitEvent.Post`）。

不改基础属性 —— 强度全部来自恶意自己的等级公式（每级 +3% 血、+2% 伤害），所以卸载 mod 后存档立刻回到「只有恶意」的原状，不会留属性残留。

### 为什么本体妖兽原来头顶没有等级（1.0.1 修的就是这个）

恶意 3.0.18 决定「要不要给这只生物挂 MobTraitCap」的条件写死在 `LHMiscs` 里：

```java
isProper(e) = e.getType().is(l2hostility:whitelist)
           || (e instanceof net.minecraft.world.entity.monster.Enemy
               && !e.getType().is(l2hostility:blacklist));
```

本体 450 个实体里 **只有 7 个继承 `Monster`**（也就是 `Enemy`），其余妖兽全是 `TamableAnimal` / `PathfinderMob`。
它们既不在白名单、又不是 Enemy，所以恶意**根本不挂能力**：不分配等级、不抽词条、头顶什么都不显示 —— 这跟有没有装适配 mod 无关。

所以 1.0.1 加了这个文件，把 91 只妖兽写进恶意的白名单：

```
data/l2hostility/tags/entity_type/whitelist.json
```

标签是合并的（replace: false），不会覆盖恶意自己或其它模组写进去的条目。

> **已禁用词条：适应（adaptive）、升空（levitation）** —— 两处同时生效：
> 1. 恶意全局配置 `config/l2configs/l2hostility-server.toml` 里 `allow_adaptive = false` / `allow_levitation = false`（对原版怪也生效）；
> 2. 本 mod 的三档配置里把这两个 id 写进 `blacklist`，并从精英档的保底词条里删掉了「适应」。
> 全局开关只管随机抽取，保底词条是配置直接给的，所以必须两边都写。

## 三档怪物

| 档位 | 等级下限 | 基准等级 | 血量倍率 | 攻击倍率 | 词条上限 | 词条 |
|---|---|---|---|---|---|---|
| 普通 malice_normal | 10 | 20 | ×1.5 | ×1.5 | 3 | 疾行、再生、血牛 |
| 精英 malice_elite | 35 | 55 | ×2.0 | ×2.0 | 5 | 疾行、血牛、再生、反击 |
| 妖王 malice_boss | 90 | 120 | ×2.5 | ×2.5 | 8 | 血牛、再生、不死、重印、杀戮光环、诸神黄昏 |

血量倍率乘在「等级加成」上：等级 L 的实际血量加成 = L × 0.03 × healthScale；攻击同理，在命中时按 L × 0.02 × attackScale 放大。

> 注意：**词条数量是按难度倍率之前的等级算的**（恶意在 fill 里一次性抽完，我们之后只调等级）。
> 也就是说噩梦档的妖王不会因为等级翻倍而多抽词条，只是更肉更疼。要词条更多就调 `maxTraitCount`。

### 分档口径

- **妖王**：攻击 ≥ 250，或名字里带「皇 / 兽王」（地牢双 Boss、风雷电狼皇、魂兽四阶、烬火魔焰熊、木魅树精四阶）
- **精英**：攻击 ≥ 90（1024 血 / 200 攻那批顶级妖兽、1000 血 / 100 攻的中坚）
- **普通**：其余可战斗妖兽（灰狼、虎、鹿、蚂蚁、木魅树精等）
- **排除**：剧情 NPC / 商人 / 幻象 / 术法特效与投射物 —— 它们在 `HostilityInitEvent.Pre` 里被取消，恶意既不分配等级也不抽词条，保持原样。

#### 覆盖范围（1.0.6 起）

判据不是「MobCategory == MONSTER」，而是**基类**：`TamableAnimal` 或 `Monster`，且最大生命 >= 40。

> 为什么改判据：第一版只扫了 MONSTER 类别，结果**鲨鱼（WATER_CREATURE）和羚羊（CREATURE）整批漏掉** —— 它们同样是 `TamableAnimal`，只是注册类别不同。玩家反馈「有些妖兽吃不到加成」就是这批 —— 共 10 只：5 条鲨鱼（冰鲛鲨/冰鳞鲨/冰魄龙纹鲨/寒渊冰鲨/玄霜鲛鲨）+ 5 只羚羊（水羚羊/碧水羚/渊跃羚/苍月羚君/洪涛覆海羚）。

- **覆盖**：所有 `TamableAnimal` / `Monster` 且有血量的实体（当前 105 只）
- **不覆盖（有意）**：
  - AMBIENT 里的**蛊实体**（白豕蛊实体、火衣蛊实体…）—— 玩家蛊虫的召唤物/特效，攻击普遍为 3
  - MISC 的 207 个投射物
  - CREATURE 里的**人物 NPC / 守卫 / 巡逻**（攻击都是 3，不参战）
  - 幻象类（绮云幻狐 幻象、胭霞万象狐 幻象）—— 跟本体狐妖一起刷，给了等级会让一场战斗变成一堆 1000 血分身

`_build/audit_ids.py` 里自带这条全覆盖自检：本体更新后跑一次，漏了谁都会直接列出来。

#### 生成路径兼容（1.0.7 起）：保险丝

恶意只在 `FinalizeSpawnEvent` 里挂载 `MobTraitCap`。本体的妖兽如果**不是走原版刷怪流程**生成的，就永远拿不到等级：

- 库层势力系统 / 据点摆怪（10.20 新增的 faction、quest、journey 模块）
- 蛊师召唤、地牢预制、脚本 `addFreshEntity`
- 存档里从旧版本带过来的怪（生成时还没有本 mod）

所以 1.0.7 加了一道保险丝：分档妖兽进场后的**下一 tick** 检查一次，

- 已有能力 → 什么都不做（不干扰恶意的正常流程）
- 没有能力 → `getOrCreate` + 按所在区块难度 `init`（init 内部会再发 Pre/Post，难度倍率与排除规则照常生效）

对已经挂载的怪**完全无副作用**；挂载失败的会打一条 WARN 并说明原因。

## 三个独立包（1.1.0 起）

本体三个版本的实体表并不相同（9.8 比 10.4/10.20 多毛僵、跳僵），所以**不再做一个通用包**，
而是按版本各出一个 jar，标签数据只包含该版本里真实存在的实体。

| 包 | 对应本体 | 白名单 | 说明 |
|---|---|---|---|
| `guzhenren_malice-1.1.0-mc98.jar` | 9.8 | 104 只 | 独立 jar，含毛僵/跳僵 |
| `guzhenren_malice-1.1.0-mc104.jar` | 10.4 | 102 只 | jar-in-jar 包装 |
| `guzhenren_malice-1.1.1-mc1020.jar` | 10.20 | 102 只 | 库层含势力/任务，必须靠补挂保险丝 |

**三个包的 modId 相同**（`guzhenren_malice`），一个整合包里只能装一个 —— 混装会 modId 冲突。

### 怎么选

看 mods 目录里本体 jar 的文件名：

| 本体 jar | 该装哪个包 |
|---|---|
| `guzhenrn蛊真人模组本体9.8.jar` | mc98 |
| `guzhenrn蛊真人模组本体10.4.jar` | mc104 |
| `guzhenrn蛊真人模组本体10.20.jar` | mc1020 |

### 装错会怎样

不会崩。jar 里带了 `malice_variant.txt` 标记，启动时和实际本体比对，不一致会直接报警：

```
[蛊真人×恶意] 装错包了：这个 jar 是给本体 10.4 用的，实际本体是 10.20。请换成 guzhenren_malice-<版本>-mc1020 那个包。
```

### 三套数据怎么来的

同一份 Java 代码（版本识别、补挂保险丝、四档难度三套共用），只有 `data/` 里的标签不同：

| 规则 | 判据 |
|---|---|
| 是否妖兽 | 基类 `TamableAnimal` 或 `Monster`，且最大生命 ≥ 10（排除 2 血的蛊虫实体） |
| 妖王 | 攻击 ≥ 250，或名字带「皇 / 兽王 / 万兽王」 |
| 精英 | 攻击 ≥ 90 |
| 普通 | 其余妖兽 |
| 排除 | 剧情 NPC / 商人 / 幻象 / 术法特效实体 |

重新生成三套数据后打包：

```
python _build/pack_jar.py --variant 98
python _build/pack_jar.py --variant 104
python _build/pack_jar.py --variant 1020
```

### 运行时的版本识别

三个包的 modId 都是 `guzhenren`、version 都是 `0.1`，FML 分不出来，所以按内容指纹识别：

| 指纹 | 9.8 | 10.4 | 10.20 |
|---|---|---|---|
| `jiang_shi_gu_xiu`（毛僵） | 有 | — | — |
| `gu_xiu` | — | 有 | 有 |
| `com.guzhenrenlibrary.faction.FactionNpcManager` | — | — | 有 |

启动日志会打 `[蛊真人×恶意] 识别到本体 10.20 —— ……`，`/guzhenren_malice info` 也会显示。


## 四档难度（玩家可随时改）

| 档位 | 命令参数 | 等级倍率 |
|---|---|---|
| 安逸 | easy / 安逸 | ×0.6 |
| 标准 | normal / 标准 | ×1.0（默认） |
| 凶险 | hard / 凶险 | ×1.5 |
| 噩梦 | nightmare / 噩梦 | ×2.2 |

`/guzhenren_malice info` ｜ `/guzhenren_malice difficulty hard`

**开局自动弹选择框**：第一次进入存档时会往聊天栏推四个可点击按钮（安逸 / 标准 / 凶险 / 噩梦），
点一下即生效，每张存档只弹一次；想再弹用 `/guzhenren_malice choose`。

难度存在存档里（`<存档>/data/guzhenren_malice_preset.dat`），换存档互不影响；权限等级 0，单人直接可用。

## 怎么判断真的生效了

1. **看日志（最硬的证据）**：进世界时 `logs/latest.log` 会出现
   `[蛊真人×恶意] 数据检查: 普通=30 精英=62 妖王=13 排除=22 ｜ l2hostility:whitelist=105 ｜ 当前难度=标准(×1.0)`。
   任何一项是 0 都会额外打一条 ERROR，说明是哪一层没加载。
2. **看头顶**：新刷出（或刷怪蛋）的妖兽名字上方应该有 `Lv.N`。老怪不会被补算 —— 恶意只在刷出那一刻分配等级。
3. **用 probe 查单只怪**：

```
/guzhenren_malice probe @e[type=guzhenren:xiong,limit=1]
```

   输出里「恶意血量修饰符：+0.90（×1.90）」就说明恶意已经接管并放大了血量；
   如果显示「无 —— 这只怪没被恶意接管」，按第 1 条的日志查是哪一层的问题。

## 显示调整（词条挤在一起）

恶意的名字牌是**一次性画的一整块文字**：等级和所有词条拼在同一个组件里，
一只妖王 8 个词条就会横着拉出去一大条，几只怪凑一起就糊成一片、把怪本身盖住。
调的不是词条数量（那会削弱强度），而是显示位置：

| 文件 | 键 | 改成 | 效果 |
|---|---|---|---|
| `config/l2configs/l2hostility-client.toml` | `showTraitOverHead` | `false` | 头顶只留 `Lv.N`，词条不再堆在怪身上 |

词条没有消失：**Jade**（已装）的实体面板会列出这只怪的全部词条（恶意自带 `TraitInfo` 兼容），准星指过去就看得到。

想要「平时不显示、瞄准谁就显示谁」，把这行改成：

```toml
showTraitOverHead = true
showOnlyWhenHovered = true
```

这份配置同时复制到了 `defaultconfigs/l2configs/l2hostility-client.toml`，重置 config 也不会丢。
