# 蛊真人升仙机制设计与原著依据

日期：2026-10-25。状态：供审阅的机制方案；本次只规划，不编译、不安装、不改变存档。

目标：以用户给定的 10.20 JAR 为依赖，在当前“天意”附属工程中补齐五转蛊师升为六转蛊仙的过程。忠实的对象是原著的条件、因果、风险和结果；不强迫所有玩家重复太白云生的个人剧情。

“完全还原”是验收目标，不能当作已完成的考据结论。下文明确区分已核原著、本体事实、游戏化设计、待核规则。待核项没有补齐前，不能宣称覆盖原著全部升仙变体。

## 1. 方案选择与范围

按用户“严格按照原著”的要求，采用完整过程模拟：碎窍、纳气、放蛊是三大步骤；灾劫、人劫、师法自然是与之交错的过程。福地与青提仙元必须实际影响游戏，不能只在界面显示六转。

技术方案由本次规划提出：沿用当前 NeoForge 1.21.1、Java 21 工程，新增升仙模块和本体兼容层。事件与公开数据接口优先；若审计证实不足，再做针对具体调用点的最小注入。前者维护成本低，后者能补未开放的本体流程但版本耦合更强，必须逐处留下证据。本次不实施任一种接入。

升仙完成后的长期仙窍经营、六转升七转、成尊、至尊仙胎蛊另立后续项目；但仙窍空间、时间、仙元、流派、落地与进入等首日必要能力属于本方案，不能全部推迟后仍宣称升仙完成。第二空窍、十绝体等升仙变体列入覆盖清单，逐条核验后交付。

## 3. 原著主线与玩家经历

### 3.1 准备：五转巅峰与个人积累

普通路线从五转巅峰出发，准备真元、本命蛊、核心蛊虫、传承知识、应劫手段与护道人，选定升仙场所。人气关乎个人底蕴、经历、才情、天赋；不等于名望、道德、击杀数或游玩时长。方正升仙的叙述明确将人气与这些因素联系起来。[第五卷《方正升仙》](https://www.hetushu.com/book/7640/5346884.html)

游戏化：本体 `renqi` 的增长语义经核实后决定复用、校正或另建有证据的积累记录。首次探索、真正炼蛊经历、流派实践等只能作为游戏中的近似载体，必须标为映射；不能靠反复捡放物品、互刷攻击或站桩刷满。不增加“善人方可升仙”的条件。

不把原著“百不存一”直接实现为固定 1% 抽奖。艰难应体现为准备、调控与真实灾劫。

### 3.2 第一步：碎窍

以真元主动冲击窍壁，直至空窍彻底破碎，打通与外界的联系；引动天气、地气及自身人气。完全碎裂是不可逆节点。原著同时写到纳气失衡的三种后果：人气偏重可自爆，天气偏多可消融，地气偏浓可化石窒息。[第三卷第二百零一章《苏醒》](https://www.hetushu.com/book/7640/5345844.html)

游戏化：玩家主动发起、持续冲击，看到裂纹扩展。尚未完全碎裂前可以停止冲击；这只是操作边界设计，不额外承诺原著中的“无伤取消”。一旦完全碎窍，关闭界面、退出、死亡重生都不能将该空窍恢复原样。不能用“失败掉一点经验再来”替代。

本命蛊、本体元海与空窍状态先做快照和托管。物品托管不代表销毁。本体仍显示五转不表示普通修炼程序还能继续生效，兼容层必须处理。

### 3.3 第二步：纳气与三气调和

天气下降、地气上涌、人气外显；蛊师亲自调控并融合三气。需要同时考虑已吸入之气、外部余气和可用人气，不以三条静止的数值条代替全过程。贪多及分心都会引发危险。实际吸收与环境供应共同影响结果，不能只由人物面板决定。

游戏化：服务端每刻演化三气。玩家分别控制天气、地气吸入和自身人气的调动；人气是有限禀赋，控制其释放不等于凭空生产。界面反馈气流偏向、身体异常与稳定趋势。调控失误应有连续预兆和可理解的原因；阈值、容错时长、输入频率都是游戏参数，不称原著数字。

`SanQi.harmony()` 的 1:1:1 数值算法是旧项目的抽象，不应直接宣称原著规定了可测量的等量比例。采用归一化比例也必须标为实现映射。

### 3.4 同时发生：天地灾劫、护道与用蛊反噬

没有及时吸收的天地二气积聚，可能演化灾劫。灾劫应由气机、地点和人物情况生成，不规定人人都遭相同九道雷。黑楼兰升仙有八重魔音劫等具体实例，并且强催蛊虫有反噬，护道人能够应对外部灾劫。[第四卷第三十五章《黑楼兰升仙（中）》](https://cn.ttkan.co/novel/pagea/guzhenren-guzhenren_691.html)

游戏化：灾劫是与纳气并发的场上事件。角色必须继续调气，护道人可以摧毁或压制灾劫载体；护道人不能替其完成三气平衡。用蛊受反噬不等于全部用蛊按钮被禁用。分别核验真实施蛊调用点、耐损及消耗，避免每刻无差别删除蛊虫。

灾劫目录必须逐个有章节依据和真实机制。八重魔音劫不能换成八只僵尸，无相手不能只做伤害弹幕。灾劫产生的临时实体不可无限刷战利品。未实现的灾劫应列缺口，不能用随机怪物充数。

人劫来自敌手、追踪与利益关系，不强制凭空刷新剧情 NPC。多人护道、袭杀、旁观都要能实际发生，但不能突破服务端既定权限。天地异象对附近人可见，精确人气、蛊方和仙窍私密数据不自动公开。

### 3.5 同时发生：师法自然

三气交感时出现直接体悟天地的窗口。方源在升仙中选择集中研究力道，而非无边界索取知识；其第二空窍的本命蛊是四转全力以赴蛊，说明普通升仙并非一律要求五转本命蛊。[第三卷第二百二十三章《枭雄黑楼兰》](https://m.hetushu.com/book/7640/5345866.html)

游戏化：只在有效交感窗口提供求知操作。用经过考据的知识条目、蛊方及残方池表现，结果按问题范围、已有基础及有限领悟额度决定；额度换算是游戏参数。选择求知不暂停三气或外界灾劫，形成真实的分心风险。可放弃追求更多领悟，不把“必须提问一次”作为升仙条件。

天意不能成为联网 AI 的任意问答机，更不能回答作品未说明的问题。已学知识与本次额度消耗都持久化，重连不刷新。高级完整仙蛊方的固定掉率及每人固定问三次均无本次原文依据。

### 3.6 第三步：放蛊、生成仙窍

在三气调和形成混元气团后投入本命蛊，触发开辟仙窍；随后投入核心蛊虫等维持形成过程。新仙窍继续吸收天地二气并逐渐定型，接引光阴支流并生成仙元。原著将这一步称为放蛊，不等同于已经把凡蛊炼成仙蛊。[第三卷第二百零四章《不自由毋宁死》](https://www.hetushu.com/book/7640/5345847.html)

游戏化：本命蛊必须是服务器确认属于该空窍的真实蛊虫；从绑定信息与实物来源进行一次转移，防止同时留在原槽和气团中。放入普通物品无效，不能按客户端提交的名字生成仙蛊。放蛊形成仙窍期间仍需应对不稳定，不可一按按钮直接结算全程。

主修方向应与该空窍本命蛊及原著对应机制关联，不由最后一秒随意点选奖励职业。普通路线不额外强制“已有仙蛊”。

### 3.7 福地定型、青提仙元与生命状态

原著给普通福地三档：小福地至多三百万亩、初生仙元十余颗；中等福地四至六百万亩、二十余颗；上等福地七至九百万亩、三十颗以上。方源个例为五百一十八万亩、二十二颗，时间比为 1:16。个例不能当成人人固定值。[第三卷第二百二十八章《终成蛊仙》](https://www.hetushu.com/book/7640/5345871.html)

游戏化：以实际成功纳入的三气、环境供给和特殊消耗结算仙窍底蕴；档次与连续规模一起保存，不将面积硬凑成没有依据的完整连续分段。面积用原著“亩”记录，游戏空间采用有说明的缩尺；不生成数百万亩全加载地图。初生仙元需选用该档文字范围内的游戏参数，不把“十余”精确化为原著固定 15。

仙窍应有主人、主修流派、面积、时间倍率、道痕记录、仙元余额与空间入口，具备基础保存和进出能力。六转使用青提仙元；仙元与凡人真元分开记账。实际道痕数量与时间倍率公式未核全，不编造统一原著常数。

升仙不等于寿命补满或永生。太白云生升仙后仍面临寿命将尽，这已直接否定“成仙自动恢复青春/加五百年寿元”的通用奖励。生命状态也不能一概设为活体：仙僵、死窍及其后果要走有原著证据的特殊路线。

### 3.8 余气升炼仙蛊与额外灾劫

仙窍形成后，若有残留天地二气、合适蛊虫和可用蛊方，可尝试借机升炼；成仙与炼成仙蛊是两个结果。方正有余气后选择升炼本命血道蛊，并面对额外风险；其后开放仙窍入口让樊西流进入护道，证明不能把“内劫外人难插手”写成绝对不能援助。[第五卷《方正升仙》](https://www.hetushu.com/book/7640/5346884.html)

游戏化：这是可放弃的机会，不强制每位蛊仙拿到仙蛊。余气不能留作无限提款；炼制消耗真实余气并触发对应内部风险。未核定本命蛊升炼失败的确切保护规则前，禁止直接套用普通炼蛊“失败销毁”算法。炼制失败与仙窍崩坏是独立判断，不自动撤销此前成功的升仙。

本体未具备的仙蛊不能只改物品名冒充：真实注册、能力、仙元消耗、饲养及唯一性都要另外补齐。唯一性按蛊种处理，不能将“六转以上同名物品”直接视为完整原著规则。

## 4. 特殊路线与必须补齐的原文

### 已有直接依据的差别

- 十绝体：黑楼兰解封后空窍能自发碎裂；普通空窍需要主动以真元冲击。场所天地二气不足会影响未来底蕴，小家子气蛊可储气并影响灾劫，但不等于自由控制灾劫。[第四卷第三十四章《黑楼兰升仙（上）》](https://www.hetushu.com/book/7640/5345921.html)
- 十绝体的人气与空窍有特殊联系；黑楼兰过程中强催排难仙蛊造成永久性损失，护道者实际承担战斗。其个例不能变成所有十绝体固定拥有排难仙蛊。[第四卷第三十六章《黑楼兰升仙（下）》](https://www.hetushu.com/book/7640/5345923.html)
- 第二空窍：方源有独立的本命蛊及主修方向。工程模型按空窍 ID 存会话，不能把一次升仙覆盖角色所有空窍。先审计本体是否具有真实第二空窍，未发现就不能虚报已兼容。
- 神不知：赵怜云升仙一章直接写明天地灾劫不加身，但调和三气仍需本人完成。此例必须进入特殊能力判定，不能说“所有人升仙必有外劫”，也不能扩大成普遍免疫所有天意后果。[第五卷《赵怜云升仙》](https://www.hetushu.com/book/7640/5346677.html)

### 发布“全部还原”前的证据门槛

以下仍需逐条找到完整章节上下文、确认版本和边界，当前不硬写结论：

1. 十绝体是否必须先有对应流派仙蛊、具体投入次序及特等福地的数值范围；不拿十种体质的读者推测表替代原文。
2. 本命蛊在普通炼制、升仙余气升炼、强催反噬中的保护区别；仙蛊唯一性的蛊种、转数和存世判定。
3. 师法自然的容量、知识边界，神不知与天外之魔是否改变这一窗口；不能由“免灾”自行推出“不能师法自然”。
4. 纯梦求真体、梦道灾劫、异人及其他独立升仙路线；至尊仙胎是特殊取得仙体方式，不能包装成普通升仙的免试按钮。
5. 仙僵升仙的先后关系、死窍形成与仙元生产；不能把方源的具体遭遇当所有失败者的通用保命方式。
6. 升仙中途移动、纳气后转移、落窍与内劫援助的限制；不能添加固定竞技场边界或越线失败。
7. 彻底碎窍后被救下但未成仙的存活条件、重开窍的合法手段；没有依据不默认“废人重练”万能重试。

这些是执行计划中的考据任务，不要求用户替开发者补答案。查不到则报告具体阻塞，保留对应路线未启用状态；不能随意省略后仍宣称完整。

## 5. 状态、并发与真实结果

### 主状态机

准备 → 冲击窍壁 → 已碎窍 → 纳气 → 放蛊开窍 → 仙窍定型 → 升仙完成。

灾劫、用蛊反噬、师法自然、外敌介入是并行子过程；余气升炼有独立结果。每阶段均可因具体原因走向不可逆失败或死亡，不设“总成功率掷骰”替代规则。

建议会话字段：`sessionId / ownerUuid / apertureId / schemaVersion / phase / phaseTick / dimension / position / profileId / brokenCommitted / qiState / insightBudget / knowledgeGrants / tribulationIds / guEscrow / apertureResult / settlementId / revision`。特殊路线通过有证据的 profile 调整规则，不在每个事件里零散硬编码人名。

初次发起前必须验证五转巅峰编码、该空窍状态、依赖指纹和必需能力。关键适配能力缺失时在碎窍前拒绝，不能让玩家碎窍后才发现没有仙窍实现。未知规则只隔离对应路线，不静默降级。

### 游戏操作参数

这些是工程默认值，不是原著定量：服务端按 20 刻/秒的 Minecraft 模拟推进；玩家调控输入每秒最多接收 10 次，单次只能提交控制意图；画面以较低频率同步并插值。不能用客户端时间结算气量或灾劫。
