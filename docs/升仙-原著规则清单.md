# 升仙原著规则与工程适配清单

审计日期：2026-10-26。目标是为天意模组的升仙实现留下一份可以追溯的边界清单。原著步骤、Minecraft 实现参数和未查明事项分开记录；“严格按原著”不允许把数值游戏化冒充成原著定论。

状态标记：

- **已核**：所引章节能支持这一条规则，或本体字节码已经确认该行为。
- **游戏映射**：为了 Minecraft 可玩性而作的实现取舍，必须标为工程参数，不得归于原著。
- **阻塞**：缺少完整原文、依赖能力或行为证据，不能开放对应路线，也不能声称全面还原。

## 可实现范围与禁止声明

当前代码已加入纯逻辑状态机（`ascension/AscensionModel.java`、`AscensionRules.java`、`AscensionMachine.java`）和 Overworld `SavedData` 会话账本（`world/AscensionStore.java`）；服务器启动时加载账本，当前尚无游戏动作写入会话。旧 `Immortal.Ascension` 已标记为弃用演示模型。玩家操作网络、界面、过程载体、真实蛊虫托管、仙窍空间和特效尚未接入；普通路线 profile 也没有启用。开始升仙需要本体修为适配、真实仙窍空间和唯一物品托管三项能力全部就绪。

下一步是补齐本体 rank/真元/人气/寿元等变量的完整读写审计，再实现可恢复的世界会话存档与真实物品托管。原著特殊路线必须按单独 profile 放行；规则未知时返回明确阻止原因，而不是默认普通路线。

现阶段不得对外称“已完整还原全部原著升仙过程”。完整声明至少要有：章节证据映射、所有承诺 profile 的支持矩阵、可靠死亡/重生处理、蛊虫唯一转移、仙窍与仙元闭环、独立服务器及多人实机记录。
