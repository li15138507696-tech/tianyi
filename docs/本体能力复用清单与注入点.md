# 本体能力复用清单与注入点（3.1.0）

> 本文件的每一条签名都由 `javap` 从真实 jar 读出，不是凭记忆写的。
> 复核方式：`python _pack/dump_refs.py && python _pack/dump_refs_extra.py`
> 原始输出在 `_pack/refs/*.javap.txt`，压平速查表在 `_pack/refs/API_SLIM.txt`。

## 一、两个本体、两层职责

| 层 | modId | 版本 | 来源 | 类数 | 我们用不用 |
|---|---|---|---|---|---|
| 外层扩展 | `guzhenren_library` | 0.1 | `D:\cxdownload\guzhenrn蛊真人模组本体10.20.jar`（sha256 `3733c20f…`） | 696（`com.guzhenrenlibrary.*`） | **用，全部世界侧系统都在这里** |
| 内层本体 | `guzhenren` | 0.1 | 上面那个包的 `META-INF/jarjar/guzhenren-0.1-neoforge-1.21.1.jar`（sha256 `b6d314d3…`） | 22371（`net.guzhenren.*`） | 用，玩家变量/蛊虫/炼蛊/标签 |

**关键事实（本轮用 zip 索引逐个核过）**：需求点名的 `FactionBrain`、`FactionTerritory`、
`FactionJourney`、`JourneyMaterializer`、`Resident`、`ResidentService`、`IdentityManager`、
`QuestLog`、`QuestLedger`、`NpcTrade`、`NpcStock` **全部在外层 `com.guzhenrenlibrary.*`，
内层 `net.guzhenren.*` 里一个都没有。**

3.0.0 的工程只把**内层** jar 放上编译 classpath，`grep` 全树对上述名字命中数为 **0** ——
也就是说，3.0.0 对势力/NPC/商贸**没有任何对接**，那些系统只是「本体里有」。

## 二、编译期接入方式（已改好）

`_pack/extract_library_api.py` 从外层包抽出 `com/guzhenrenlibrary/**` 生成
`_pack/libs/guzhenren_library-api.jar`（2.95 MB / 697 条目），已加入
`_pack/javac_check.py` 与 `_pack/javac_probe.py` 的 classpath。

`neoforge.mods.toml` 增加硬依赖：

```toml
[[dependencies.tianyi]]
modId = "guzhenren_library"
type = "required"
versionRange = "[0.1,)"
ordering = "AFTER"
side = "BOTH"
```

不这么写，附属会在只装内层本体的实例上加载到一半才因 `NoClassDefFoundError` 崩掉。

## 三、复用的既有能力（只列我们真正调用的）

全部调用收敛在 `net.guzhenren.tianyi.bridge.GuzhenrenBridge` 一个类里。

### 3.1 势力

| 能力 | 真实签名 | 我们怎么用 |
|---|---|---|
| 取势力账本 | `FactionTerritory.of(Level)` | 每次需要时按维度取，不缓存 Level |
| 势力状态 | `FactionTerritory.state(FactionDef)` → `State{treasury,power,supplies,alive,owner,destroyedBy}` | 读资金/实力/补给/存亡 |
| 补给 | `addSupplies(FactionDef,int):int` | 物流抵达后加补给（不写自家账本） |
| 实力 | `addPower(FactionDef,int):int` | NPC 行动成效 |
| 国库 | `addTreasury(FactionDef,long):long` | 掠夺/赔付 |
| 立场 | `stance(FactionDef,FactionDef):FactionStance`、`addStance(…,int):int` | 天意挑动/缓和势力的唯一合法入口 |
| 势力枚举 | `FactionTerritory.playerFactions()` + `FactionPool.ALL`（`Seed.domain/name/tier`）+ `FactionDef.byName(String)` | 构造可用势力集合；解析不到就跳过 |
| AI 轮次 | `FactionBrain.tick(ServerLevel)`、`runRound(ServerLevel,FactionTerritory,long)` | **不重写**，只在需要时让本体自己跑 |

`FactionBrain` 另有 `ally/declareWar/blame/makePeace/absorb/exterminate`
（均 `(ServerLevel, FactionTerritory, FactionDef, FactionDef)`）—— 附属的「人劫」只推动
这些既有决策，不另建一套宣战/结盟。

### 3.2 行程（商队 / 使者 / 军队）

| 能力 | 真实签名 |
|---|---|
| 列表 | `FactionTerritory.journeys()` → `FactionJourneys.all()/size()/byId(int)/activeCount(long)` |
| 登记 | `record(ServerLevel,FactionDef,FactionDef,JourneyKind,long,long):FactionJourney` |
| 推进 | `tick(ServerLevel,FactionTerritory,long)`、`settleTeam(...)`、`markFailed(FactionJourney,FactionTerritory,long)` |
| 类型 | `JourneyKind.ARMY / ENVOY / CARAVAN`（`minMembers/maxMembers/baseDuration/settlesOnArrival/membersFor(long)`） |
| 行程字段 | `id/fromKey/toKey/kind/startTick/duration/members/seed/payload/settled/failed/phase/escortId/joinerId/entityIds/memberNames/progress(long)` |
| 实体化 | `JourneyMaterializer.tick(ServerLevel,long)`、`sweepOrphans`、`abandon(int)`、`materializedCount()` |

**结论**：商队运输不需要我们自己造。附属要做的是给行程**挂货物批次**并接管结算，
而不是再造一个「抽象商队」。`FactionJourney.addEntityId(UUID)` / `entityIds()` 可以把
我们关心的承运实体挂到既有行程上。

### 3.3 NPC 生活

| 能力 | 真实签名 |
|---|---|
| 登记表 | `ResidentRegistry.of(Level)`、`ResidentService.registry(Level)`、`all()`、`get(UUID)`、`aliveCount()` |
| 实体映射 | `ResidentService.residentOf(Entity)`、`findLive(ServerLevel,Resident):Mob` |
| 推进 | `ResidentService.tick(ServerLevel)`、`simulate(ServerLevel,Resident,long[,Map])` |
| 居民状态 | `npcId():UUID`、`displayName()`、`zhuanshuInt()`、`cultivation()`、`dimension()`、`x/y/z()`、`positionKnown()`、`state():State`（`IDLE/CULTIVATING/TRAVELLING/SEEKING_GU/VISITING/WITH_PARTNER`）、`stateUntil()` |
| 关系 | `partners()`、`feuds()`、`addFeud(UUID)`、`addPartner`、`household()`、`isHouseholdLord()` |
| 知识与日志 | `log():List<String>`、`latestLog()`、`remember(String,long)`、`gu()`、`rememberGu(String)` |
| 移动 | `travelTo(double,double,double)`、`at(dim,x,y,z,tick)`、`setState(State,long)` |
| 持久化 | `toTag()/fromTag(CompoundTag)` |

**结论**：情报的「持有者」就是 `Resident.npcId()`；`Resident.remember` 是既有的生活日志入口，
不要另建一套 NPC 记忆。居民自带 `feuds` 表，人劫的仇敌关系写这里。

### 3.4 身份

`IdentityManager`：`active(Player)`、`activeId(Player):UUID`、`activeTitle(Player)`、
`identities(Player):List<PlayerIdentity>`、`find(Player,UUID)`、`findByName`、
`switchTo(ServerPlayer,UUID):boolean`、`switchToName`、`create/rename/delete`。

**结论**：身份是 `UUID`，不是名字。情报与证据一律按身份 UUID 记，
所以「切换身份」天然不会抹掉已经成立的事实 —— 前提是我们不按名字合并。

### 3.5 商贸与寿蛊

| 能力 | 真实签名 |
|---|---|
| 货币 | `NpcTrade.currency()`、`countCurrency(Player)`、`consumeCurrency(Player,int)`、`priceOf(Item):int` |
| 货架 | `NpcTrade.shelf(Mob,NpcPersona,int):List<Offer>`、`Offer{item,basePrice,price,category,stock,soldOut()}` |
| 库存 | `NpcTrade.countInInventory(Mob,Item)`、`takeOne(Mob,Item)`、`availableKinds(...)` |
| **补货** | `NpcStock.restock(Mob):int`、`NpcStock.tick(Mob):int`、`dueForRestock(long,long)` |
| 保护 | `NpcStock.isProtected(Mob,ItemStack)`、`protectedId(String,String)`、`PROTECTED_KEY`、`RESTOCK_KEY` |
| 寿蛊 | `NpcStock.longevityIds():Set<String>`、`isLongevityGu(ItemStack)`、`longevityName(String)`、`LONGEVITY_KEYWORD` |

**结论**：寿蛊审计必须用 `longevityIds()` 这份本体清单，不能按名字含「寿」自己猜。
补货接管点是 `NpcStock.restock(Mob)` / `tick(Mob)`。

### 3.6 任务

`QuestLog`、`QuestLedger`、`QuestLedgerData` 见 `_pack/refs/API_SLIM.txt` 第 669~722 行。
本轮**没有**新建任务系统；NPC 行动通过既有的 `Resident` 状态与 `FactionMission` 表达。

## 五、注入点

**本轮没有任何 Mixin。**

`verify_jar.py` 会强制检查 jar 里既没有 `.mixins.json`、也没有 `mixin` 类、
也没有 `META-INF/jarjar/*.jar`（防止把本体整包打进来）。

理由：桥接层只用本体的**公开静态入口**（`FactionTerritory.of` / `ResidentRegistry.of` /
`NpcStock.restock` / `IdentityManager.*`），这些都不需要改本体字节码。
一旦必须注入，必须在本文件里记下「目标方法 + 版本依据 + 为什么非注入不可」。

## 六、未核实项（不要当成已验证）

- `FactionDef.byName(String)` 对 `FactionPool.Seed.name()` 的解析成功率**只在编译期验证过签名，
  没有实机验证**。桥接层对解析失败是跳过而不是抛异常，所以失败表现为「势力数量少一些」，
  不会崩。
- `FactionTerritory.of(Level)` 在非 overworld 维度是否返回同一账本，**未实机验证**。
- `ResidentService.findLive` 在区块未加载时的返回值，**未实机验证**。
- 以上三项都需要进游戏用测试存档确认，静态分析无法替代。
