## 二、B09 为什么没修

报告指出 `PursueAction` 往居民 feud 表写玩家身份 UUID，但本体
`ResidentService.findDuelTarget` 只扫描 Mob、要求双方互为实体 UUID 仇怨且都有居民档案，
**玩家身份不满足这条目标获取链**，所以「追捕」实际只是下了移动命令。

要真修，需要先确认本体对玩家身份的**通缉/敌对入口**。我本轮核对了 `_pack/refs/`
里的 `npc.javap.txt` / `api_slim`，只看到 duel 相关能力，没有看到「对玩家通缉」的公开接口。
在拿不到证据前硬接，只会把一个「看起来能追捕」的空壳换成另一个。

因此本轮的处理是：
- 保留 `PursueAction` 现有行为，但**不把它算作已实现的追捕**；
- 在文档里明确「已下达移动命令 ≠ 已完成追捕」；
- 等核实到入口再接。

## 五、仍然存在的边界（没有因为这次修复而消失）

1. **没有进游戏实测。** 本轮所有验证仍是编译 + 离线断言 + 静态审计 + 打包校验。
2. **`FactSource` 的目击仍不看视线遮挡**：现在只做三维距离 + 高度窗口，
   没有做 raycast，所以「隔一堵墙但同高度」仍算目击。
3. **布局/灾劫仍未持久化**：B01 修好了机缘的持久化，但 `Ploy` / `Calamity.Run`
   仍是运行期状态，重启即消失（旧文档已承认）。
4. **炼蛊产物仍是推断**：会话 + 拾取扣除 + 唯一候选只能把污染压到最低，
   本体不暴露产物 ID 这条根本限制没变。
5. **B09 未修**（见第二节）。
