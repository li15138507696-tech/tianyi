## 2. 应优先修复的 bug

P1 表示主要玩法或核心约束失效；P2 表示部分场景行为错误。诊断程序中的成功断言是在证明旧版本存在异常，不是在证明问题已修复。

### B01 · P1：扶持机缘始终走不到资源点创建

位置：[WorldExec.java:161](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/world/WorldExec.java:161)。

`support` 每次调用 `propose` 新建机缘，紧接着在同一时刻检查 `offer.mature(now)`。机缘至少酝酿 2400 刻，检查必然不通过，随后直接返回。下一次扶持仍新建机缘；调度器没有处理旧的已成熟机缘。`WorldSites.create` 因而没有正常可达的扶持路径。

复现：按相同的 propose → mature 调用顺序推进 240 次，已有机缘成熟，但进入产地创建分支的次数始终是 0。影响资源、传承及气运缩短酝酿的实际收益。

修复方向：申请与兑现分开调度，按持久化机缘 ID 处理成熟、过期、已兑现；只有真实创建产地成功才标记兑现，重复调用不再产出。

### B02 · P1：处于盲区的玩家仍把实时真实数据带入决策

位置：[Observation.java:104](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/world/Observation.java:104)、[Assessment.java:251](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/Assessment.java:251)。

Actor 在检查载体触达、遮蔽之前，已写入真实实力、资源、道德、气运和维度。不可观测分支仅修改增长、置信度、hidden，没有以历史情报替换这些值。评估器仍把隐藏玩家的真实实力计入总量和份额。

复现：隐藏且置信度为 0 的玩家实力从 1 改为 1000，另一可见玩家的实力份额立刻从约 90.9% 变为约 0.99%。这会改变对可见玩家的判断。

另外，`Observation.java:146` 的炼蛊见证只检查 `!covered`，没有检查载体触达。因此“无载体但未显式 cover”的场景仍能写入炼蛊情报。

修复方向：真实快照与可知画像分离；决策仅接受有来源和时间的知识快照。无观测来源时不读取实时变化作为天意知识。

### B03 · P1：姿态翻转没有接入决策，压制过的人不会正常转回扶持

位置：[WillCore.java:236](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/WillCore.java:236)、[WillCore.java:327](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/WillCore.java:327)。

`switchPosture` 有实现，但生产源码中没有调用。扶持分支对已有 SUPPRESS 姿态直接跳过；目标后来变弱、已符合有用棋子的条件，也不会因此退出该姿态。

复现：相同的弱小、有用玩家画像，在新决策器中获得 SUPPORT；带有旧 SUPPRESS 姿态的决策器不给 SUPPORT。

修复方向：每轮根据有效情报更新姿态，并明确活动布局、冷却与姿态之间的关系。

### B04 · P1：压制永久限两次，失败执行也耗掉机会

位置：[WillCore.java:192](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/WillCore.java:192)、[WillCore.java:217](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/WillCore.java:217)。

计数键为 `suppress:目标`，没有区分手段、时间窗口或活动布局。达到 2 后永久拒绝压制，且计数会保存。计数在意图生成时增加，此时世界执行尚未发生；落点不可用或布局开启失败也没有回滚。

复现：同一个强大逆天目标，计数为 2 的决策器在 100 游戏日后仍不发 SUPPRESS；相同画像的新决策器会压制。

这不符合“持续根据局势奖惩”，也不是“最多同时叠加两次”。修复方向：采用活动上限或可恢复的时间窗口配额；由真实执行结果结算次数和预算。

### B05 · P1：炼蛊证据仍可被拾取物品污染

位置：[AlchemyWitness.java:74](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/world/AlchemyWitness.java:74)、[AlchemyTracker.java:70](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/will/AlchemyTracker.java:70)。

产物被定义为“背包中增加数量最多的本体物品”，没有绑定蛊方实际产出。`GuFang` 仅出现在说明字符串中。同期拾取、交易或取出本体物品都会污染差分。

两个异常已复现：

1. 实际产物增加 1 个，同时捡到无关本体物品 64 个，最终把后者记为炼成产物。
2. 进度从 20 归零时，背包基线被删除，Tracker 的 `seenBelow` 却不清除；后续到 100 时，可把既有库存作为新增产物。

证据进入知识库和身份案，会影响后续判断。修复方向：给炼制尝试分配会话 ID，核对蛊方、真实产物产生入口及成功状态；无可靠来源的背包差分只能作为待核实线索。失败、取消、换方、重连分别结束或恢复会话。

### B06 · P2：正常整组拾取漏记采集事实

位置：[TianyiEvents.java:65](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/TianyiEvents.java:65)。

Post 拾取事件传给 `FactSource` 的是 `itemEntity.getItem()`，即拾取后的剩余物品。整组进入背包时数量已归零，`isGuMaterial` 会拒绝空栈，事实、目击和后续调查均缺失。

已核对 NeoForge 本地字节码：先调用 `Inventory.add`，再派发 Post；该事件提供 `getOriginalStack()` 和 `getCurrentStack()`。

修复方向：以原始栈和当前栈的数量差计算真实拾取数量，只记录正差值；不要把剩余数量当作拾取数量。

### B07 · P2：兽群重复扣数，非同类击杀也会扣账

位置：[BeastHerds.java:171](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/world/BeastHerds.java:171)、[BeastHerds.java:217](D:/daima/mcmod/天意/src/main/java/net/guzhenren/tianyi/world/BeastHerds.java:217)。

驱赶时 `drive` 已扣种群，生成兽携带 `tianyi_herd`；之后击杀同一只兽，`recordKill` 又调用 `harvest(1)`。复现：10 只种群赶出并杀死 1 只后账面为 8。

无标记的受害者也会按附近兽群扣数，未核对物种。上游死亡钩子对所有由玩家击杀的 LivingEntity 调用此入口，因此杀附近无关动物或 NPC 也会污染种群账。

此外，预扣后生成失败没有返还；`WorldExec.java:290` 对驱赶结果为 0 直接走无种群扣减的生成兜底，包含种群耗尽场景。

修复方向：区分未实体化种群、已实体化个体和死亡；每个实体只转移/结算一次，按物种和归属核验；生成失败返还预留，耗尽时停止生成。

### B08 · P2：崩溃兽群永久不能恢复

### B09 · P2：追捕使用了 NPC 相互决斗的仇怨接口

### B11 · P2：目击只核对水平距离，隔墙和上下层居民也会知道

## 3. 缺少的系统接线：按八项本体补全要求

以下是完成度差距，不把每一项都算成新增 bug。

1. **情报来源还不完整。** `FactSource` 目前只产生 HARVEST。抢夺、杀人、交易和真实委托结果没有完整进入 WorldFact → 持有者 → 行动链；因此现有 actionFor 中追捕分支没有正常对应的事实来源。需要补事件来源、实际目击与传播后的可信度门槛，不能直接广播全服。
2. **凡人反侦察尚未成为正常生存玩法。** Counter 的应用入口目前主要是 OP 命令和自定义标记，缺少本体具体蛊虫/器物使用、代价、清除载体及后续恢复的接线。纯状态机存在不等于玩家可通过本体机制操作。
3. **资源点未与真实环境及压制链闭合。** `WorldSites` 有储量、恢复与归属，但成熟入口被 B01 阻断；现有压制的资源退化主要操作自建仙窍资源表，并未正常调用地表 `scrambleOwnedBy` 等路径。还缺本体资源来源、生态变化、破坏事件及归属争夺验证。
4. **有限商人和真实商队物流缺失。** `CargoBatch` 是自建计时批次，交付时直接在收货人当前所在维度/位置掉落，没有绑定本体 FactionJourney 商队、实际路线、护卫或截货。桥接注释提到 RestockGuard，但仓库没有该实现，也没有接管原生补货。寿蛊只清点了 ID，并新增自然供给；NPC 原生补货仍从候选池生成物品。因此“审计全部寿蛊 ID”不能当作“控制全部未来来源”。
5. **兽群尚未成为与本体共享的野生生态。** 当前是少量物种的虚拟种群与新实体生成。缺自然出生、繁殖、捕捉、卸载、死亡之间的统一个体归属与守恒；迁徙主要移动账面锚点，实际个体迁徙和栖息地重评未形成闭环。
6. **NPC 利益与人劫还缺真实动机和结果。** 现有调查主要下达移动命令；追捕存在 B09。另一人劫路径仍生成新 NPC 并 setTarget，尚未按已有居民利益、关系、所属势力和行程挑选执行者。需要真实到达、识别、失败/撤退及结果证据；复用本体关系与委托，不另造一套。
7. **炼道研究与传承联动缺失。** 当前炼蛊见证主要写 CRAFT 与身份痕迹，且存在 B05；并未构成真实尝试 → 诊断缺项 → 研究进展 → 已验证传承知识的链条。需要核对具体炼制成功产出入口；失败记录可用于研究，但同一失败不能反复换收益。
8. **持续世界状态与结果反馈未闭合。** B03/B04 阻断持续姿态变化和压制。IntelState 的事实、行动计划有保存，但 WillCore 内另一套 Ploy、Calamity、Opportunity 没有保存。NBT 往返已复现三者清空。该限制在旧技术边界文档已承认，因此这是已知缺口，不包装成新发现；与“重启后布局继续、机缘期限可靠”的目标仍有差距。

关于道德、气运：目前道德影响抽象社会代价与人劫渠道选择；气运主要影响机缘酝酿时长。没有完成本体关系、具体事故与利益变化之间的结果反馈，且 B01 使气运对应机缘很难落地。补齐时应保留天意的局势目标，用道德决定社会反应，用气运调整有边界的遭际；不要把善恶分数直接等同于天意喜恶。

关于升仙：**不列待办，不因存在 Immortal 模型继续扩张升仙功能。** 现有普通登录创建仙窍记录、击杀高档妖兽降低宿命完好度等自定义映射，应单独核对是否保留，不能称作本体已确认流程。
