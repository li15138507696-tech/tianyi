# 3.10.2 兼容与可靠性

本次只交付可靠性切片，停在 3.10.2 验收；有限资源点骨架未接入、未启用，植物增长仍未实现，不宣称 3.11 完成。注册 ID、payload ID、旧存档键保持不变，不安装真实实例，不删除旧数据。本次 C 没有命令执行工具，下面均为待主代理执行的命令，未声称编译、测试、出包通过；未实机验证。

## 行为修复

- `tianyi_encounters` 的已知 schema 1/无版本已知格式加载后保存为 schema 2，保留 phase/baseGranted/stakePaid/settled/penaltyPending。加载不执行奖励、退款、处罚或生成。
- 未来/非法 schema、坏行、缺关键奖惩标记、重复 owner、错误列表类型整账隔离，保留完整原 NBT，包括未知字段。隔离账本不创建新玩家记录、不奖励、不处罚、不清除旧妖兽/木桶。采取整账隔离是避免坏行 owner 无法确认时生成第二份玩家账；需管理员在副本审查修复。
- 限制存档金额、计时和同步字符串长度，防负数、溢出和异常包；合并提示文本不超过原 payload 的 1024 字符。
- 生成仍先确认 addFreshEntity 成功，再扣款，再 startBattle；补查生成回调已杀死/移除目标的情形，生成失败不扣款。调查、胜利、处罚消费先标记幂等状态及 dirty 再执行效果。满背包沿用归属玩家的地面掉落；落物被拒绝时记录未送达数量，停止本次余量，禁止自动重放。
- 未加载/未知实体不再触发十秒后自动返押金；不是击杀证据。原挑战明示超时、死亡、离场等规则仍有效。关闭旧斗兽时进行记录冻结，退出、死亡、复活或切维度不另行处罚。
- 退出清理斗兽限流、见闻待发队列、播报和炼蛊观测；停服清理连接玩家观测及全局斗兽/见闻临时容器。服务端 tick 扫待同步玩家，10 刻限流内的最终状态不会直接丢弃；同步与限流使用主世界时钟。登录、复活、切维度会请求本人见闻同步。
- `legacyAutomaticResources=false` 独立默认隔离旧产地创建、靠近吐物、拾取自动归属和物流。保留既有库存及在途批次，重新启用后沿用旧逻辑处理。`legacyAutomaticPressure=false` 保持不变。
- 普通猎兽仅记录种群与本人证据，不据此计逆天或损宿命；拾取旧产地和旧机会物品均不代表道破，不引发雷雨。

## 实际限制

SavedData 与玩家背包、地面物品、实体分别保存，硬崩溃不具跨文件原子性。dirty 只是保存标记，不能当作即时磁盘提交。本版不能保证任意断电都不丢失或重放奖励。取消掉落后的日志需要人工核对，不能自动按金额补发。生成 API 异常及第三方事件拒绝仍需故障注入与实机验证。

无游戏运行证据：生成取消、死亡/退出、切维度、未加载实体、满背包、重启、最后状态同步和第三方兼容性均待隔离实例验证。实际 runtime API 的新增使用仅为既有标准 NBT/ListTag/Entity 方法，签名仍以主代理 javac/probe 结果为准。
