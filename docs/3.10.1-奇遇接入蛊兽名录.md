# 3.10.1：奇遇系统接入蛊兽名录（6 只 → 89 只，属性来自字节码）

## 一、改了什么

奇遇系统 `encounter/EncounterBeasts` 原本是**手写的 6 只**：

```
灰狼 20/0/3 · 土狼 20/0/3 · 熊 40/10/10 · 红熊 40/10/10 · 灰熊 40/10/10 · 电狼 60/3/5
```

现在：

| 项 | 之前 | 现在 |
|---|---|---|
| 名单 | 手写 6 条 | **名录 89 只**（`BeastCatalog`） |
| 属性 | 手写常量 | **本体字节码抽取**（`BeastStats`，脚本生成） |
| 阶/道/名 | 无 | 来自名录，说明文字里带「雷道·百兽」这种标注 |
| 门槛 | 手写 minRank | **阶与血取高**（见下） |

## 二、属性是抽出来的，不是估的

本体把属性写在实体类的 `createAttributes()` 里，没有 JSON 可读。所以：

```
_pack/gen_beast_stats.py   逐类 javap -c -p，取
                          Attributes.MAX_HEALTH / ARMOR / ATTACK_DAMAGE 后面的常量
        ↓
_pack/_beast_stats.json    中间产物
        ↓
_pack/gen_beast_table.py   生成 encounter/BeastStats.java（89 行，勿手改）
```

**校准**：先用这套办法抽那 6 只已核实的兽，结果与手写值**完全一致**
（灰狼 20/0/3、熊 40/10/10、电狼 60/3/5），才推广到全名录。89 只全部抽取成功，0 失败。

## 三、门槛为什么不能只看阶

抽出来才发现本体数值并不统一：

| 兽 | 名录阶 | 原生生命 |
|---|---|---|
| 电狼 | 1（特殊种） | **60** |
| 豹 / 彪 / 赤狐 | 1（特殊种） | **1000** |
| 冰魄龙纹鲨 | 1（特殊种） | **1024**（护甲 70、攻击 200） |

只按阶定门槛，新手会在 0 级撞上 1000 血的豹。所以：

```
minRank = max(阶门槛, 血门槛)
阶门槛：1→0  2→1  3→2  4→3  5→4
血门槛：<100→0  <300→1  <800→2  <2000→3  其余→4
```

结果：**89 只里 9 只 0 门槛**（灰狼、土狼、工兵蚁这类），65 只门槛 ≥3。

## 四、说明文字

每只兽的劝告都是按真实数值生成的，例如：

> 雷道·百兽。原生生命 240、护甲 4、攻击 12。会使用本流派蛊虫，注意其状态效果。
> （数值为初始属性，未含词条与状态效果。）

血量 ≥800 的会额外提醒「血量远超同级，别按体型判断强弱」——
因为本体的数值确实不讲道理。

## 五、验证

```
名录 89 条 ↔ 本体 jar：id 全部存在、名字一致、档位词与阶数一致
属性表 89 条 ↔ 名录：一一对应（不多不少），阶/道/名一致
属性表 89 条 ↔ 本体字节码：逐条比对生命/护甲/攻击，不符 0 只
```

- `_pack/audit_bestiary.py` 现在是**三重核对**，且第 3 步用**单次 javap 批量反汇编**
  （89 只只用 2.4 秒，不是 89 次调用）。它同时锁住「生成表不许手改」。
- `EncounterBeastsTest` 重写：池子与属性表条数一致、成员必须在名录里、
  原生属性合法、门槛与「阶/血取高」一致、默认兽在首位、
  rank 1–9 的确定性与**可达性**（3000 个种子内每个符合条件者都要能抽到）、池子不可变。

实测输出：

```
EncounterBeastsTest passed (89 catalog beasts, rank0=9, rank>=3=65, deterministic gates)
```

## 六、边界

1. **属性是初始值**：不含本体词条、转数威压、状态效果，实机数值更高；
   说明文字里已明确写「原生」与「未含词条」。
2. **没有实机验证**：谁在什么群系刷由本体决定，本模组只引用。
3. **名录补了 4 只知识库没列的常见兽**：灰狼、土狼、熊、灰熊 ——
   它们本来就在奇遇池里，删掉会是功能倒退，所以按 1 阶、道归「无」收录并注明。
4. **同一套属性抽取也可用于本体其它系统**（例如按血量调灾劫强度），本轮没做。
